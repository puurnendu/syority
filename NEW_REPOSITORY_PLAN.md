## Phase 1 — Files that must NEVER enter Git

These paths hold secrets, regenerable artifacts, or tenant/runtime data. They must be excluded by `.gitignore` (see `.gitignore.recommended`) and scrubbed before the first commit if they currently sit in the working tree as candidates.

## Phase 5 — Exact commands to create a brand-new Git repository

**DO NOT EXECUTE in this pass.** Run only after cleanup + `.gitignore` swap + secret scrub, on approval.

### 5.1 Prerequisites (manual)

1. Confirm `.env` and `pw.txt` will not be staged.  
2. Copy `.gitignore.recommended` to `.gitignore` (or merge by hand).  
3. Ensure `.env.example` exists and has **no** real secrets.  
4. Move/delete Temporary + Secrets per Phase 3 (or ensure ignored).  
5. Choose a **new** empty remote (GitHub/GitLab). Do not push to the old broken remote until you control access and history policy.

### 5.2 Retire broken metadata (destructive to `.git` only — not application files)

```bash
# From the project root (PowerShell or bash).
# This removes ONLY the broken .git directory. It does not delete app/, src/, prisma/, etc.

# PowerShell:
Remove-Item -Recurse -Force .git

# bash:
# rm -rf .git
```

### 5.3 Initialize new repository

```bash
git init -b main

# Ensure ignore file is the recommended one
# PowerShell:
Copy-Item -Force .gitignore.recommended .gitignore

# bash:
# cp .gitignore.recommended .gitignore

git status
```

### 5.4 Stage and verify nothing secret is included

```bash
git add -A
git status

# Explicit denylist checks (must print nothing important):
git diff --cached --name-only | findstr /I ".env pw.txt uploads node_modules .next certbot"
# bash equivalent:
# git diff --cached --name-only | grep -E '\.env$|pw\.txt|^uploads/|node_modules|\.next|certbot' || true

# If .env.example is missing from the index:
git add -f .env.example
```

### 5.5 First commit

```bash
git commit -m "Initial commit: Aurianoa OS production baseline from laptop working tree"
```

### 5.6 Add remote and push

```bash
git remote add origin https://github.com/<org-or-user>/<new-repo-name>.git

git push -u origin main
```

### 5.7 Optional: protect main + add deploy key on VPS later

```bash
# On VPS after clone (later milestone — not now):
# git clone -b main https://github.com/<org-or-user>/<new-repo-name>.git /var/www/aurianoa
```

### 5.8 Local secret hygiene after init

```bash

# Rotate any password that lived in pw.txt
```

## Phase 6 — Migration checklist (verify before VPS cutover)

Use this after the new repo exists and before calling the system “production-ready.”

### Application builds

- [ ] `npm ci` (or `npm install --legacy-peer-deps` if peer conflicts remain)  
- [ ] `npx prisma generate`  
- [ ] `npm run build` succeeds (or known blockers documented)  
- [ ] `npm run dev` starts on expected port (3001 per `package.json` scripts)

### Docker works

- [ ] `docker compose version` ≥ 2.24 (for `ports: !reset`)  
- [ ] `docker compose -f docker-compose.yml -f docker-compose.prod.yml config` validates  
- [ ] Images build: `docker compose -f docker-compose.yml -f docker-compose.prod.yml build`  
- [ ] Stack starts; `app` health endpoint responds inside container network

### Prisma works

- [ ] `prisma/schema.prisma` is the only live schema  
- [ ] `npx prisma migrate deploy` strategy agreed for greenfield vs existing DB  
- [ ] Seed path documented (`PLATFORM_ADMIN_EMAIL` / `PLATFORM_ADMIN_PASSWORD` via `.env`)  
- [ ] No reliance on loose untracked `.sql` at `prisma/migrations/*.sql` for deploy

### Uploads ignored

- [ ] `uploads/` is gitignored and untracked (`git check-ignore -v uploads`)  
- [ ] Compose mounts `uploads_data` (or equivalent) for `/app/uploads`  
- [ ] Laptop `uploads/` backed up separately before any wipe

### Secrets removed

- [ ] `pw.txt` not in git; deleted or outside repo; password rotated  
- [ ] `.env` not in git; `git check-ignore -v .env`  
- [ ] `.env.example` tracked and free of real secrets  
- [ ] No `public/safety` / tenant media in the first commit  
- [ ] Remote is the **new** repo URL (not the broken/unreachable old remote unless verified)

### Repository clean

- [ ] `git status` works (new repo)  
- [ ] No `tsc_errors*.txt` / root `check-*.js` in the initial commit (or explicitly accepted)  
- [ ] `git log -1` shows the initial baseline commit  
- [ ] Clone into a temp directory and confirm app files present without `node_modules`/`.env`

### Disaster recovery readiness (preflight)

- [ ] Know where Postgres data lives (volume name)  
- [ ] Know where uploads live  
- [ ] Backup/restore scripts planned (later phases)  
- [ ] DNS + TLS plan documented
