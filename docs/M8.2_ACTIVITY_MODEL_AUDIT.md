# M8.2 — Activity Model & Relational Audit

## 2. Activity Relationships (`ActivityRelationship`)

| Field Name | Type | Nullable? | Default | Description |
|---|---|---|---|---|
| `id` | `UUID` | No | Random UUID | Primary key. |
| `organization_id` | `UUID` | No | — | Tenant foreign key. |
| `predecessor_id` | `UUID` | No | — | Foreign key to predecessor `Activity.id`. |
| `successor_id` | `UUID` | No | — | Foreign key to successor `Activity.id`. |
| `relationship_type`| `Enum` | Yes | `FS` | `FS` (Finish-to-Start), `SS` (Start-to-Start), `FF` (Finish-to-Finish), `SF` (Start-to-Finish). |
| `lag_days` | `Int` | Yes | `0` | Lead / Lag duration offset. |

---

## 3. Scoping & Predecessor Rules for the Planning Grid

1.  **Shutdown Scoping:** Every activity created or updated in the planning grid MUST receive `event_id = activeEventId` and `organization_id = session.organization_id`.
2.  **Predecessor Scoping:** Both `predecessor_id` and `successor_id` must belong to the active `event_id` and the same `organization_id`. Cross-shutdown or cross-tenant logic ties are strictly prohibited.
3.  **Duration & Dates Arithmetic:**
    *   `planned_end = planned_start + (duration_hours / 8 or 24 working hours)`
    *   Default duration is 8 hours (1 shift).
