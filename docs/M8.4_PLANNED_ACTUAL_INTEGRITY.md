# M8.4 — Planned vs Actual Integrity Verification

This document defines and verifies the separation between **Planning Baseline Dates** and **Field Execution Actuals** in SYORITY.

---

## 1. Column Boundary Definition

```
┌──────────────────────────────────────────────┐
│             PLANNING DOMAIN                  │
│  • Activity.planned_start                    │
│  • Activity.planned_end                      │
│  • Activity.duration_hours                   │
│  • Activity.early_start / early_finish       │
│  • Activity.late_start / late_finish         │
│  • Activity.total_float / free_float         │
│  • Activity.is_critical                      │
│                                              │
│  ==> AUTHORITATIVE BASELINE                  │
│  ==> UNTOUCHED BY FIELD EXECUTION            │
└──────────────────────────────────────────────┘
                       ▲
                       │
             STRICT BOUNDARY WALL
                       │
                       ▼
┌──────────────────────────────────────────────┐
│            EXECUTION DOMAIN                  │
│  • Activity.actual_start                     │
│  • Activity.actual_end                       │
│  • Activity.progress_percent                 │
│  • Activity.status                           │
│  • Workpack.overall_progress                 │
│  • Workpack.status                           │
│                                              │
│  ==> FIELD RECORD OF REALITY                 │
└──────────────────────────────────────────────┘
```

---

## 2. Integrity Proof & Invariant

*   Updating `actual_start` or `actual_end` in field execution updates execution progress without altering `planned_start` or `planned_end`.
*   Schedule recalculations evaluate baseline planned dates unless the planner explicitly updates the plan.
*   Workpack variance is derived strictly by comparing `actual_start`/`actual_end` against `planned_start`/`planned_end`.
