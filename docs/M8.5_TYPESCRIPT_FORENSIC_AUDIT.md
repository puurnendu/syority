## Root Cause Analysis

### Systemic Pattern 1 — Implicit `any` (185 errors, 16.2%)

**Error codes**: TS7006, TS7031, TS7053, TS7005, TS7034, TS7022, TS7016

**Root cause**: `strict: true` in `tsconfig.json` combined with untyped callback parameters, destructured bindings, and dynamic object indexing. Almost entirely concentrated in:
- `ta-dashboard.tsx` (140 of 185)
- Various test files and report providers

**Fix**: Add explicit type annotations. Not M8.5 related.

### Systemic Pattern 2 — `orgId` / `org_id` naming mismatch (16 errors)

**Root cause**: Prisma schema uses `organization_id` (snake_case). Some application code passes `orgId` (camelCase) to Prisma queries. This is a systemic naming convention inconsistency predating M8.5.

**Affected files**: `export/generate/route.ts`, `export/history/route.ts`, `export/search/route.ts`, and several `app/api/` routes.

### Systemic Pattern 3 — Stale field references (334 errors)

**Error codes**: TS2339, TS2551

**Root cause**: Property names changed during schema evolution (e.g., `activityId` → `activity_id`, `logDate` → `log_date`, `projectCode` → `code`). Code referencing old camelCase names was never updated.

### Systemic Pattern 4 — Object literal type mismatches (239 errors)

**Error codes**: TS2353, TS2561

**Root cause**: Prisma `create`/`update`/`where` calls using properties that don't exist on the generated Prisma types (renamed fields, removed relations, incorrect includes).

### Systemic Pattern 5 — Type assignment failures (280 errors)

**Error codes**: TS2322, TS2345

**Root cause**: Passing incompatible types to functions, missing required properties in object literals, incorrect return types.

### Prisma Client Regeneration

Prisma Client v7.9.1 regenerated successfully. The regeneration updated type signatures to include new fields, which causes new fields to appear in error messages for unrelated pre-existing errors (e.g., s-curve route), but does NOT introduce new type incompatibilities.

### `Prisma.JsonNull` Requirement

Prisma 7.x uses a discriminated union for JSON fields: `InputJsonValue | NullableJsonNullValueInput | undefined`. Raw `null` is not in this union — must use `Prisma.JsonNull`. This caused the single M8.5-introduced error in `templates.ts:126`.
