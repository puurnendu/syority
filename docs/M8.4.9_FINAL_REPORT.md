### Hold Point Dual Model

**[ARCHITECTURE DECISION]** Hold Points have TWO representations:

1. **Scheduling identity** — Hold Point activities in the HP family are real activities with:
   - Duration (typically 2h)
   - Predecessors/successors
   - Progress tracking (0% or 100%)
   - Float and critical path participation

2. **QA control identity** — The `hold_point_type` field on any activity:
   - HOLD = blocking QA gate requiring inspector clearance
   - WITNESS = non-blocking observation point
   - null = no QA requirement

These are NOT duplicates. A template uses HP.* activities for scheduling, and the
`hold_point_type` attribute for QA control enforcement.

## Export Architecture

### is_exportable Is NOT Sufficient Alone

**[FINDING]** `ActivityUdfDefinition.is_exportable` only covers UDF-based attributes.
7 of 14 export attributes are NON-UDF native model fields (Discipline, Phase, Equipment Tag, etc.).

**[RECOMMENDATION]** For M8.5:
- Use `is_exportable` on ActivityUdfDefinition for UDF-based exports (P0)
- Hardcode the 7 known native field export mappings in the P6 export adapter code
- Defer `ExportAttributeConfig` table to M9 for admin UI configuration
