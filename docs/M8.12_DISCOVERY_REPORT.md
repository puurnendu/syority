### Key Finding for CPM Integration
- Activity has `early_start`, `early_finish`, `late_start`, `late_finish` — these are outputs from CPM

- **No existing constraint mechanism** that feeds into Early Start calculation beyond predecessor relationships and `planned_start` dates

## C. CPM Engine — Integration Boundary

### scheduleEngine.ts (PROTECTED — 461 lines)

**Input Interface** (`ScheduleActivityInput`):
```typescript
id, activity_number, description, duration_hours
planned_start, planned_end, wbs_code, status, discipline_id
```

**Key Finding: Forward Pass (Line 239-280)**
The forward pass calculates Early Start by:
1. Activities with no predecessors: ES = max(0, planned_start - project_start)
2. Activities with predecessors: ES = max(predecessor EF + lag) for FS relationships

**CRITICAL: The engine does NOT currently accept external constraints.**

The `ScheduleActivityInput` interface has `planned_start` but this is used as a soft baseline date, not a hard constraint. An activity's ES is driven solely by predecessor logic.

**Safest Integration Boundary**: 
- **Option A**: Add an optional `constraint_date` to `ScheduleActivityInput` that the forward pass respects as a floor for Early Start
- **Option B**: Add material constraints as synthetic predecessor relationships (virtual FS with lag)  
- **Option C**: Post-process CPM results — adjust Early Start after CPM runs (weakest, loses transitive impact)

> **LOCKED RECOMMENDATION**: Option B is safest — it does NOT modify `scheduleEngine.ts`. Material constraints are expressed as synthetic "material milestone" activities with FS relationships to dependent activities. The CPM engine naturally propagates the constraint through the network.

### Coexistence Architecture
Material constraints and resource constraints operate independently:
- Resource constraints: "Do we have enough people/equipment?"
- Material constraints: "Do we have enough materials on-site?"

Both can constrain an activity's effective start date. They should be computed independently and the binding constraint wins.

## E. M8.9 Scenario System

### Services Audited (PROTECTED)
- `ScenarioDomainService` — resolves effective activities
- `ScenarioCalculationService` — runs CPM + resource analysis
- `ScenarioPlanningService` — scenario CRUD

### Scenario Material Integration
The `ScenarioCalculationService.calculate()` method:
1. Resolves effective activities (with scenario overrides)
2. Runs `calculateSchedule()` (CPM engine)
3. Runs `ResourcePlanningService` + `ResourceConstraintService`
4. Computes Schedule Health Index

**Material constraint integration point**: After step 1 (resolve effective activities), material readiness dates can be injected as additional constraints before step 2 (CPM). This maintains the non-mutating guarantee — material ETAs are projected, not written.
