## 4. DEVIATIONS & MINOR ISSUES
1. **Activity Number Unique Constraints:** The original plan mapped template activity codes directly to Workpack activity `activity_number`. However, the live schema has a `UNIQUE(organization_id, activity_number)` constraint on `Activity`. This was successfully bypassed in testing by prefixing the `activity_number` with a unique workpack ID/run ID, which is the correct behavior for isolated instantiations.
2. **Dashboard Config:** Test 16.5 (Dashboard Config table isolation) reported `MISSING`, as no `DashboardConfig` table exists in the current database iteration. This is a non-blocking issue as dashboards are currently derived via real-time queries rather than stored configurations.
3. **Resource Default Seeds:** The `Resource` table constraint on `resource_type_id` prevented immediate test-seeding of missing default profiles, but the structural linking between `ActivityLibrary` and `activity_code_default_resources` was successfully verified.
