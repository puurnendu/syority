## Existing Security Architecture

All M8.12 APIs MUST use the established security pattern:

### 1. withTenantGuard

```typescript
export const GET = withTenantGuard(async (req, { params }, session) => {
  // session.user.organization_id is the tenant boundary
  // session.user.id is the authenticated user
});
```

### 2. guardApi

```typescript
const { error } = await guardApi('nav.schedule');
if (error) return error;
```

### 3. Organization-Scoped Queries

```typescript
const data = await prisma.materialConstraint.findMany({
  where: {
    organization_id: session.user.organization_id, // NEVER user-supplied
    event_id: eventId,
  }
});
```

## M8.12 Route Security Plan

| Route | Methods | Guard | Permission | Notes |
|-------|---------|-------|------------|-------|
| `/api/events/[eventId]/materials/constraints` | GET | withTenantGuard | nav.schedule | Material constraint summary |
| `/api/events/[eventId]/materials/readiness` | GET | withTenantGuard | nav.schedule | Readiness dashboard |
| `/api/events/[eventId]/materials/supply` | GET, POST | withTenantGuard | nav.schedule | Supply records |
| `/api/events/[eventId]/materials/supply/[id]` | PATCH, DELETE | withTenantGuard | nav.schedule | Individual supply record |
| `/api/events/[eventId]/materials/recalculate` | POST | withTenantGuard | nav.schedule | Trigger constraint recalculation |

---

## IDOR Protection

- Material constraints are scoped by `organization_id` + `event_id`
- Supply records are accessed through material lines which are scoped by `organization_id`
- No direct access to records by ID without org validation
- All parent record ownership verified before child operations

---

## No Parallel Security Mechanism

M8.12 MUST NOT introduce:
- Custom authentication middleware
- Custom session handling
- Custom role/permission checks outside `guardApi`
- Direct database access without tenant filtering
