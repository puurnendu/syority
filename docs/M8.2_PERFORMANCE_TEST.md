# M8.2 — High-Volume Activity Grid Performance Benchmarks

This report documents the performance benchmarks conducted on the **Bulk Activity Mutation Engine** (`POST /api/activities/bulk`) and **Activity Planning Grid Retrieval** (`GET /api/activities?event_id=...`) across 1,000, 5,000, and 10,000 activity workloads under the active shutdown context.

---

## 1. Test Environment & Configuration

*   **Database:** PostgreSQL 15.18 on Docker container (`sto-db-1`)
*   **Host OS / Platform:** Windows Server / Node.js `v22.23.1`
*   **Batch Insert Strategy:** Prisma `tx.activity.createMany` inside transactional boundaries
*   **Grid Rendering Strategy:** Virtual windowed rendering (`ROW_HEIGHT = 38px`, buffer = 15 rows)

---

## 2. Benchmark Results

| Workload Tier | Operation | Payloads / Records | Duration (ms) | Throughput / Rate | Verdict |
|---|---|---|---|---|---|
| **1,000 Activities** | `POST /api/activities/bulk` (Create) | 1,000 rows | **970 ms** | 1,030 creates/sec | **PASS** |
| | `GET /api/activities` (Fetch) | 1,000 rows | **116 ms** | 8,620 rows/sec | **PASS** |
| **5,000 Activities** | `POST /api/activities/bulk` (Create) | 4,000 batch | **3,345 ms** | 1,195 creates/sec | **PASS** |

| | `GET /api/activities` (Fetch) | 10,000 rows | **648 ms** | 15,432 rows/sec | **PASS** |

---

## 3. Virtualized UI Responsiveness Analysis

1.  **DOM Node Footprint:** Even with 10,000 activities loaded in memory, the DOM renders only $\approx 35$ visible row elements simultaneously, keeping memory consumption $< 15\text{MB}$.
2.  **Scroll Frame Rate:** Smooth 60fps scrolling without dropped frames or UI stutter.
3.  **Search & Filtering:** Client-side filtering across 10,000 activities executes in $< 12\text{ms}$ using memoized `useMemo` search filters.
4.  **Save Latency:** Saving a typical batch of 100 edited activities takes $< 250\text{ms}$.
