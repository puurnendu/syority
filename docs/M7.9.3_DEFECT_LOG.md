## Defect Inventory & Resolution Summary

### DEF-001: Workpack ID Code Generation Fallback ("none")
*   **Severity:** P1 (Business Workflow Defect)
*   **File:** [`src/lib/workpackId.ts`](file:///c:/DEV/STO/src/lib/workpackId.ts), [`src/modules/Workpack/Services/WorkpackService.ts`](file:///c:/DEV/STO/src/modules/Workpack/Services/WorkpackService.ts), [`app/api/workpacks/route.ts`](file:///c:/DEV/STO/app/api/workpacks/route.ts)
*   **Problem:** Workpack creations resulted in `workpack_id_code: null` in the database, causing the UI and test suites to fall back to `'none'`.
*   **Root Cause:**
    1.  `workpack_id_counters` table does not have `@default(uuid())` on `id` or `@default(now())` on `updated_at`. `tx.workpack_id_counters.upsert` threw Prisma validation errors because `id` and `updated_at` were omitted.
    2.  `WorkpackService.createWorkpack` did not accept or map `workpack_id_code`.
    3.  `app/api/workpacks/route.ts` only generated `workpack_id_code` if both `unit_code` and `primary_discipline` strings were passed in the body, instead of generating default prefixes (`GEN-GEN-001`).
*   **Surgical Fix:**
    1.  Injected `id: crypto.randomUUID()` and `updated_at: new Date()` in both `create` and `update` clauses of `workpack_id_counters.upsert` in `src/lib/workpackId.ts`.
    2.  Added `workpack_id_code?: string | null` to `WorkpackService.createWorkpack` input and data map.
    3.  Updated `app/api/workpacks/route.ts` to resolve and auto-generate `workpack_id_code` prior to workpack creation.
*   **Test:** Executed `scratch/test_workpack_id.js` creating multiple consecutive workpacks.
*   **Result:** Verified consecutive code generation: `U10-MEC-001`, `U10-MEC-002`, `GEN-GEN-001`, and custom code `CUSTOM-WP-999`. **(PASS)**

### DEF-002: Tenant Isolation HTTP Status Masking
*   **Severity:** P2 (Security / API Correctness)
*   **File:** [`app/api/workpacks/[id]/route.ts`](file:///c:/DEV/STO/app/api/workpacks/[id]/route.ts)
*   **Problem:** Cross-tenant IDOR access attempts returned HTTP 500 instead of standard HTTP 403 Forbidden.
*   **Root Cause:** `assertTenantAccess` threw an error with `.statusCode = 403`, but the route catch block ignored the status code property and returned a hardcoded `500`.
*   **Surgical Fix:** Updated the catch block to return `(error as any).statusCode || 500`.
*   **Test:** Executed `scratch/m792_tenant_test.js` where Tenant B queries Tenant A's workpack.
*   **Result:** Correctly returns `403 Forbidden` with body `{"error":"Resource not found or access denied"}`. **(PASS)**

### DEF-003: Schedule Calendar Raw SQL Table Name Mismatch
*   **Severity:** P1 (Tenant Provisioning Blocker)
*   **File:** [`src/core/Platform/TenantProvisioningService.ts`](file:///c:/DEV/STO/src/core/Platform/TenantProvisioningService.ts)
*   **Problem:** Tenant Provisioning failed and aborted transactions with `relation "schedule_calendars" does not exist`.
*   **Root Cause:** Service executed raw SQL `INSERT INTO "schedule_calendars"`, but the database table name is `"ScheduleCalendar"`.
*   **Surgical Fix:** Replaced raw SQL insert with type-safe `tx.scheduleCalendar.create` in `stepCalendars`.
*   **Test:** Re-ran tenant provisioning for Tenant A and Tenant B.
*   **Result:** Synchronous provisioning succeeds with `201 Created` and all standard calendars populated. **(PASS)**
