# M8.4.4 — Plan vs Actual Quantity Model

> **M8.4.4** — Generated: 2026-08-15T06:53:26.785Z
> Classification: FACT | INFERENCE | RECOMMENDATION | UNKNOWN

## Problem Statement
A single percentage (e.g., "Progress: 50%") is insufficient for quantitative activities like welding or scaffolding. Management reporting requires Plan, Actual, and Remaining quantities.

## Quantity Semantics by Activity Type

| Quantity Type | Unit | Additive across Equipment? | Progress Method |
|---|---|---|---|
| **Scaffolding** | m³ | YES | Actual m³ / Plan m³ = % |
| **Welding** | Inch-dia (id) / kg | YES | Actual id / Plan id = % |
| **Painting** | m² | YES | Actual m² / Plan m² = % |
| **Blinds** | Nos | YES (Count) | Inserted / Total = % |
| **QA Holds** | Nos | YES (Count) | Cleared / Total = % |

## SYORITY UDF Actuals Gap
**[FACT]** The current `ActivityUdfValue` table stores a SINGLE value (the plan). There is no native tracking for ACTUAL UDF quantities over time.

**[RECOMMENDATION]** RECOMMENDATION: To support Plan vs Actual for quantities, SYORITY must either:
1. Log actual quantities in `ProgressLog` (preferred for time-series tracking).
2. Add `actual_value_number` to `ActivityUdfValue` (simpler, but no history).

> **[RECOMMENDATION]** For M8.5, modifying `ProgressLog` to accept an optional `quantity_actual` field is the most defensible architecture for quantity-based progress.
