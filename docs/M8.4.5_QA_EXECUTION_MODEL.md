## P6 QA Architecture

**[FACT]** P6 uses TWO SEPARATE Activity Code Types for QA:

| Code Type | Values | Meaning |
|---|---|---|
| iPlan_Hold Point AI | HPAIFST, HPAISTG, HPAILST | Asset Integrity inspections (First/Stage/Last) |
| iPlan_Hold Point TS | HPTSFST, HPTSSTG, HPTSLST | Technical Services inspections (First/Stage/Last) |

### CRITICAL CORRECTION
**[FACT]** Previous milestones modeled QA as a single hold_point_type (HOLD|WITNESS|null).
**[FACT]** The P6 XER reveals QA is actually a TWO-DIMENSIONAL classification:

| Dimension | Values | Purpose |
|---|---|---|
| AI Stage | First / Stage / Last | When in the AI inspection sequence |
| TS Stage | First / Stage / Last | When in the TS inspection sequence |

An activity can have BOTH an AI hold point AND a TS hold point simultaneously.

**[RECOMMENDATION]** SYORITY should model QA hold points as two separate optional fields on Activity:
- hold_point_ai: FIRST | STAGE | LAST | null
- hold_point_ts: FIRST | STAGE | LAST | null
