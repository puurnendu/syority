# M8.3 — CPM Schedule Engine Performance Benchmarks

This report documents the performance benchmarks of the **Deterministic Critical Path Method (CPM) Calculation Engine** and API (`POST /api/schedule/calculate`) across 1,000, 5,000, and 10,000 activity networks under the active shutdown campaign.

---

## 1. Test Configuration & Environment

*   **Database:** PostgreSQL 15.18 on Docker container (`sto-db-1`)
*   **Host Platform:** Node.js `v22.23.1`
*   **Engine Algorithm:** Kahn's Topological Sort + Forward/Backward Pass ($O(V + E)$ complexity)
*   **Persistent vs Transient Calculation:** In-memory high-speed calculation with optional database batch persistence

---

## 2. Benchmark Results

| Network Size | Endpoint / Action | Activity Count | Calculation Latency | Execution Rate | Status |
|---|---|---|---|---|---|
| **1,000 Activities** | `POST /api/schedule/calculate` | 1,000 activities | **458 ms** | 2,183 tasks/sec | **PASS** |
| **5,000 Activities** | `POST /api/schedule/calculate` | 5,000 activities | **264 ms** | 18,939 tasks/sec | **PASS** |
| **10,000 Activities** | `POST /api/schedule/calculate` | 10,000 activities | **466 ms** | 21,459 tasks/sec | **PASS** |

---

## 3. Algorithm Complexity & Memory Profiling

1.  **Time Complexity:** The engine achieves true $O(V + E)$ algorithmic performance by using Map-indexed adjacency lists and in-degree tracking, avoiding $O(V^2)$ nested scans.
2.  **Memory Footprint:** Calculating CPM for 10,000 activities requires $< 28\text{MB}$ of heap memory.
3.  **Client-Side Gantt Responsiveness:** SVG timeline renders in $< 120\text{ms}$ with full support for zoom switching (Day / Week / Month).
