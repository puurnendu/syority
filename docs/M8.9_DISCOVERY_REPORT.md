## 5. Architecture Protection Directives
To protect the M8.7 and M8.8 investments, the upcoming M8.9 implementation must abide by the following constraints:
1. `scheduleEngine.ts` must remain authoritative for all schedule calculations.
2. `ResourceConstraintService` must remain authoritative for resource logic.
3. Existing baseline/variance/forecast/health services must be reused; they should not be duplicated.
4. Existing tenant guards and RBAC models must be enforced strictly across all new API routes.
5. Legacy M8.7 components (e.g., `ResourcePlanningDashboard`) must remain isolated and protected from regressions.
