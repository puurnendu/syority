## CRITICAL DISCOVERY — iPlan Field Architecture

**[FACT]** iPlan uses CONFIGURABLE custom fields on its entities. Each field can be independently configured for P6 export as either:

1. **Not Exported** (id=0) — field stays in iPlan only
2. **Activity Code** (id=1) — exported as a P6 Activity Code Type with enumerated values
3. **User Defined** (id=2) — exported as a P6 UDF with arbitrary data

### CRITICAL CORRECTION — Quantity Fields Are NOT P6 UDFs

**[FACT]** The P6 XML (fff.xml) contains ZERO UDFType or UDFValue elements.
**[FACT]** The P6 XER contains 6 UDF Types, but they are all scheduling metadata (MSP Activity ID, Critical Path, etc.), NOT workpack quantities.

**[FACT]** Therefore: Scaffolding (M3), Painting (M2), and Insulation (M2) are iPlan-ONLY fields that are NOT exported to P6.

> This overturns all previous assumptions that treated these as "P6 UDFs".
> These are **iPlan planning quantities** that exist only within the iPlan/workpack domain.

**[RECOMMENDATION]** SYORITY must natively model these quantities on the Activity (or via ActivityUdfValue), but should NOT attempt to export them as P6 UDFs unless the P6 administrator specifically requests it.

## iPlan P6 Export Configuration System

**[FACT]** iPlan has a full "Primavera Configuration" UI (Scripts-application.txt:25911-26400) where administrators:
1. Select iPlan fields to include in export
2. Configure each field as Activity Code or UDF
3. Set Activity Code scope (Global/EPS/Project)
4. Map iPlan field names to P6 display names

**[INFERENCE]** This means the set of P6 Activity Code Types is NOT fixed — it is whatever the iPlan administrator has configured. The 13 types we see in the XML/XER represent the HMEL-specific configuration.
