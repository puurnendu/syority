## RECOMMENDATION

> **[RECOMMENDATION]** Use **Option 2: Family.Type** as the Activity Code structure.

### Rationale

1. **Equipment Type** is already a property of the Workpack and Template — embedding it in the Activity Code creates redundancy and prevents cross-equipment reuse
2. **Execution Phase** (Window) is a SCHEDULING dimension, not an IDENTITY dimension — it should remain separate
3. **Family.Type** naturally groups activities for reporting, filtering, and template design
4. **Cross-equipment reuse**: "Scaffolding" is the same activity whether on an HE or a Vessel — only the quantity differs
5. **P6 alignment**: P6 uses SEPARATE Activity Code dimensions — Family and Type map cleanly to two P6 Activity Code types
