### SQL Aggregation Example (Efficient)

```sql
-- Duration-weighted progress per event (single query)
SELECT 
  event_id,
  CASE 
    WHEN SUM(COALESCE(duration_hours, 0)) > 0 
    THEN ROUND(SUM(COALESCE(progress_percent, 0) * COALESCE(duration_hours, 0)) / SUM(COALESCE(duration_hours, 0)))
    ELSE ROUND(AVG(COALESCE(progress_percent, 0)))
  END as weighted_progress,
  COUNT(*) as total_activities,
  COUNT(*) FILTER (WHERE status = 'completed' OR progress_percent = 100) as completed,
  COUNT(*) FILTER (WHERE progress_percent > 0 AND progress_percent < 100) as in_progress,
  COUNT(*) FILTER (WHERE progress_percent = 0 OR progress_percent IS NULL) as not_started
FROM "Activity"
WHERE event_id = $1 
  AND organization_id = $2 
  AND deleted_at IS NULL 
  AND status != 'cancelled'
GROUP BY event_id;
```

This is **one query** vs the current pattern of loading all activities into memory and iterating.
