> An admin should be able to tick a checkbox and export it.

## Finding: is_exportable Insufficient for Non-UDF Attributes

7 of 14 export attributes are NOT UDFs — they are native model fields:
- Discipline → `activity.discipline_id`
- Phase → `activity.window`
- Equipment Tag → `workpack.asset_id`
- etc.

`ActivityUdfDefinition.is_exportable` cannot control these.

## P0 Solution (M8.5)

Hardcode the known export mappings in the P6 export adapter:
- Activity Codes: Discipline, Phase, Unit, System, Equipment Tag, Contractor, Permit, Hold Point AI
- These are always exported (P6 requires them)
- UDF-based attributes (quantities) use `is_exportable` flag

## P1 Solution (M9)

```
ExportAttributeConfig:
  id               UUID
  organization_id  UUID
  attribute_name   String    — "Level Code", "Scaffolding Qty"
  source_type      String    — "NATIVE" | "UDF"
  source_field     String    — "activity.window" or UDF code
  export_target    String    — "P6_ACTIVITY_CODE" | "P6_UDF" | "P6_NATIVE"
  export_name      String    — P6 field name
  is_enabled       Boolean   — admin toggle
```

This is NOT needed for M8.5. Defer to M9.
