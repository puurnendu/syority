# M8.0 — Architectural Decisions & Strategy

This document records the architectural and commercial decisions formulated during M8.0 to evolve the frozen M7.9.4 technical baseline into the standalone **SYORITY Shutdown Management System**.

---

## 1. Product Model: Company → Site → Multiple Shutdowns

### Decision
Adopt the **Single Company → Primary Site → Multiple Shutdown Campaigns** operational model as the primary user experience.

### Architectural Rationale
*   In real industrial facilities, a refinery or chemical plant does not recreate its physical assets, process units, or piping specifications every time a turnaround occurs.
*   **Persistent Foundation:** The physical hierarchy (Site → Plant → Area → Unit → System → Equipment Tag) and master standards (Gasket/Bolt ratings, standard procedures, contractor directories) belong to the Site and remain permanent.
*   **Transient Campaigns:** Each shutdown (`TA-2026`, `TA-2028`, `Emergency-2031`) is linked to the Site and acts as an operational container for scope items, WBS activities, dynamic schedule, workpacks, shift logs, and QA/QC clearance records.
*   **Baseline Alignment:** In M7.9.4, `Event` (Shutdown) already references `site_id` and `organization_id`, and serves as the foreign key (`event_id`) on Workpacks, Activities, and Safety records. This structure is already natively supported by the database without schema changes.

## 2. Commercial Model: Free Core Installation + Cloud AI Tokens

### Decision
The core shutdown management software is **Free to Install & Run with Unlimited Users**. Commercial monetization is achieved exclusively through **SYORITY AI Cloud Tokens**.

### Key Rules & Mechanics
1.  **Local-First & Offline Resilience:**
    *   The core software (PostgreSQL + Next.js + Redis) runs locally on-premise, in the plant control room, or on local laptops.
    *   Planning, scheduling, workpack printing, flange torque calculation, QA hold points, safety logs, and dashboard analytics require **zero internet connectivity**.
2.  **Syority AI Cloud Gateway:**
    *   AI capabilities (Workpack Auto-Fill, P&ID Drawing Extraction, Voice Memo Progress Transcribing, Report Generation) make outbound HTTPS calls to the Syority Cloud AI Gateway using an organization API token key.
3.  **Token Balance Carry-Forward:**
    *   AI tokens purchased for a turnaround (e.g., 500,000 tokens) do not expire at the end of the shutdown window. Unused balances remain attached to the organization account and automatically carry forward to future turnarounds (`TA-2028`, `Pitstop-2029`).
4.  **Graceful Zero-Balance Degradation:**
    *   When the AI token balance reaches zero or the installation is offline, the core software continues running normally with 100% functionality. AI action buttons gracefully display a polite *"Top up AI Credits to auto-generate"* prompt without disrupting work.

## 3. User & Licensing Model

### Decision
Provide **Unlimited Users per Installation/Shutdown**; eliminate per-seat licensing friction.

### Rationale
*   Turnaround teams involve plant managers, lead planners, discipline engineers, field execution supervisors, contractor foremen, safety officers, and QA inspectors.
*   Imposing a 5-user or per-seat license cap creates immense operational friction in high-intensity turnaround environments, leading teams to share passwords or revert to Excel spreadsheets.
*   Allowing unlimited local users encourages 100% digital adoption across all field contractors, which in turn dramatically increases the usage and value of Syority AI services.

## 4. Simplification & Platform Feature Parking

To deliver a razor-sharp, zero-bloat product experience, complex SaaS multi-tenant overhead in M7.9.4 is categorized as follows:

| Component / Area | Action | Rationale |
|---|---|---|
| **Multi-Tenant Onboarding Wizard** | **PARK / HIDE** | Standalone installations use a streamlined 1-step local plant setup wizard. |
| **SaaS Billing & Stripe** | **PARK / REMOVE LATER** | Replaced by cloud prepaid AI token license keys. |
| **Tenant Cloning & Provisioning Jobs** | **PARK** | Single-site standalone installations do not require automated tenant cloning. |
| **Platform Telemetry & Host Metrics** | **PARK** | Retained for troubleshooting; hidden from operational shutdown menus. |
| **OIS Cockpit Multi-TV Sharing** | **SIMPLIFY** | Focused into a dedicated fullscreen *"Situation Room"* dashboard for the active shutdown. |

## 6. Dashboard: The 30-Second Situation Cockpit

In a turnaround control room, the primary dashboard must answer six critical questions in under 30 seconds:

1.  **Are we on schedule?** (Overall planned % vs actual % S-Curve).
2.  **What is driving the critical path today?** (Zero-float activities highlighted in red).
3.  **What are our immediate lookahead tasks?** (Next 24h and 72h critical handovers).
4.  **Are workpacks ready for tomorrow's shift?** (100% ready vs missing materials/permits).
5.  **Are there active field constraints?** (Blocked activities awaiting cranes, scaffolding, or permits).
6.  **Is safety compliant?** (Today's safe manhours, active PTW count, zero LTIs).

## 7. Architecture Risks & Mitigations

| Risk | Impact | Architectural Mitigation |
|---|---|---|
| **Air-gapped Plant Networks** | Remote plants cannot connect to external APIs. | Core software is 100% local and offline-first; AI features degrade gracefully with zero core interruption. |
| **Large Schedule Rendering (5,000+ activities)** | UI latency during live planning meetings. | Use virtualized rendering for the activity grid and client-side web workers for CPM calculation. |
| **Field Data Conflicts** | Multiple supervisors updating the same workpack concurrently. | Use optimistic locking with revision indicators (`updated_at` timestamps). |
| **Large Workpack PDF Generation (100+ pages)** | Memory spikes during batch print export. | Stream PDF binary buffers in background worker with pagination chunking. |
