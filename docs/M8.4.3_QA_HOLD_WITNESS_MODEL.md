### Hold Point Characteristics (from corpus)

- **[FACT]** Hold Points are ACTIVITIES in Section E that also appear in Section G/H
- **[FACT]** They have explicit durations representing INSPECTOR EFFORT, not activity duration
- **[FACT]** They reference a DISCIPLINE: AI (Asset Integrity) from Section G, TS (Technical Services) from Section H
- **[FACT]** They specify team count (typically 1-2 inspectors)
- **[INFERENCE]** The duration on a Hold Point represents how long the inspection takes, not how long the work is blocked
- **[INFERENCE]** Blocking duration could be LONGER than inspection duration if inspector is unavailable

### Witness Point Characteristics

- **[FACT]** Witness Points are typically on TEST activities (Hydrotest, Pneumatic Test)
- **[FACT]** Duration is often 0 (inspector observes ongoing work, no additional time)
- **[INFERENCE]** Work can proceed after notification if inspector is unavailable after a reasonable wait

## RECOMMENDATION

### Hold Point Representation

```
Activity {
  hold_point_type: "HOLD"   // or "WITNESS" or null
  hold_point_description: "Pre Cleaning Inspection By AI"
  discipline_id: <AI discipline UUID>
  // Inspector effort modeled via:
  ActivityResource {
    resource_type: "labor"
    resource_name: "AI Inspector"
    planned_hours: 6.0
    headcount: 1
  }
}
```

### Clearance Flow

```
1. Activity reaches execution
2. IF hold_point_type = "HOLD":
     → Activity status = "on_hold"
     → Inspector notified
     → Inspector performs inspection
     → qa_clearance_records created (cleared_by, cleared_at)
     → Activity status = "in_progress" → "completed"
3. IF hold_point_type = "WITNESS":
     → Activity proceeds normally
     → Inspector notified (advisory)
     → IF inspector arrives: qa_clearance_records created
     → IF inspector unavailable: Activity completes without clearance
```

### Progress Weighting

> **[RECOMMENDATION]** Hold Points should NOT distort progress percentage. A 2-hour inspection should not have the same weight as a 160-hour retubing activity.

Recommended weighting: **Duration-weighted progress** (already standard in P6)

```
Progress = Σ(activity_progress × activity_duration) / Σ(activity_duration)
```

This naturally gives Hold Points proportional weight based on their actual duration.
