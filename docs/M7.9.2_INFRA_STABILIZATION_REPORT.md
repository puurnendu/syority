# M7.9.2 — Infrastructure Stabilization Report

This report details the diagnostics and stabilization performed on the Syority Docker development and testing environment.

## Root Cause

### Redis
- **Issue:** `Bind for 0.0.0.0:6379 failed: port is already allocated`
- **Root Cause:** A duplicate, running Redis Docker container (`syority-redis`) outside of the current Docker Compose project was already bound to host port `6379`. This prevented the compose-managed `sto-redis-1` container from successfully binding to the same port.
- **Resolution:** Stopped and removed the duplicate `syority-redis` container.

### Migrator
- **Issue:** `service "migrator" didn't complete successfully: exit 1`
- **Root Cause:** 
  1. The `migrator` container inherited `DATABASE_URL` directly from the host `.env` file, which mapped to `localhost:5432`. Inside the container, `localhost` referred to the container itself (where no database runs), leading to `connect ECONNREFUSED 127.0.0.1:5432`.
  2. The Docker images on the host were built 2 hours ago and were missing 3 new migration files that were present on the host filesystem.
- **Resolution:**
  1. Updated `docker-compose.yml` to override `DATABASE_URL` internally inside the container network to point to the correct service name and credentials: `postgresql://user:pass@db:5432/syority?schema=public` (with optional environment override via `DATABASE_URL_DOCKER`).
  2. Rebuilt the Docker Compose images to synchronize code changes and include all 18 migration files.
