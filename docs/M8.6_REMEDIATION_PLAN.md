# M8.6 Remediation Plan

This plan documents the actions required to close the gaps identified during the M8.5 acceptance process.

## GAP-01: Activity Number Architecture
- **Current Status:** Incorrectly conflated Activity Code and Activity Number. Previous attempt used `{WORKPACK_NUMBER}-{SEQUENCE}`.
- **Corrected Action:** 
  - Create a new utility `activityNumberGenerator.ts` to assign Activity Numbers based on the formula: `<EQUIPMENT_TAG>-<SERIAL_NUMBER>`.
  - Fetch the existing `activity_id_increment` from the `Organization` configuration (falling back to 3 if unset).
  - Use 4-digit zero padding (e.g. `31-E-116-0005`).
  - Maintain the existing `@@unique([organization_id, activity_number])` schema constraint.
  - Implement concurrent safety during sequence generation.

## GAP-02: Transaction Boundary Design
- **Action:** Ensure `TemplateLibraryService.instantiate` wraps its database modifications in a `prisma.$transaction`.

## GAP-03: P6 / MS Project Export
- **Action:** Ensure `app/api/export/generate/route.ts` injects `<ExtendedAttribute>` (`FieldID 188743739`) correctly for the MS Project XML export. Maintain separation between `activity_code`, `activity_number`, and `activity_id`.

## GAP-04: M9 Dashboard Scope
- **Action:** Defer M9 dashboard work to a future milestone.
