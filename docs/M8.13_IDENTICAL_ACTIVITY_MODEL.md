# M8.13 Identical Activity Model

## Current State Assessment

### Can the system reliably identify identical activities across equipment?

**NO** — not with current data model alone.

### What exists today

| Element | Model/Field | Status |
|---------|------------|--------|
| Equipment identity | `Asset.tag_number`, `Asset.asset_type` | ✅ Exists, reliable |
| Equipment type (Asset) | `Asset.asset_type` (free text) | ⚠️ Free text, no FK |
| Equipment type (Workpack) | `Workpack.equipment_type` (free text) | ⚠️ Free text, no FK |
| Equipment type (Template) | `workpack_templates.equipment_type` (free text) | ⚠️ Free text, no FK |
| Equipment type master | `EquipmentType` model (id, name, code) | ✅ Exists, underused |
| Activity classification | `Activity.description` (free text) | ❌ Not normalized |
| Activity library link | `Activity.activity_library_id` → `ActivityLibrary` | ⚠️ Sparsely populated |
| Activity code | `ActivityLibrary.activity_code` (optional) | ⚠️ No standard taxonomy |
| Work type taxonomy | `WorkType` (category + name + code) | ✅ Exists, structured |
| Template family | `TemplateFamily` (equipment_type, code) | ✅ Exists, structured |
| Template activities | `workpack_template_activities` (description, activity_code) | ⚠️ Code optional |
| Template → workpack link | `WorkpackInstantiation.template_id` | ✅ Exists for template-created WPs |

### Gap Analysis

The chain **Equipment → Equipment Type → Standard Activity → Activity Instance** is broken at:

1. **Equipment → Equipment Type**: `Asset.asset_type` is free text, not FK to `EquipmentType.id`
2. **Equipment Type → Standard Activities**: No mapping table exists
3. **Standard Activity → Activity Instance**: `Activity.activity_library_id` is sparsely populated; `ActivityLibrary` has no `equipment_type` or `standard_activity_type` field

### Minimum Additional Data Model Required

```prisma
/// Standard Activity Type — canonical activities for a given equipment type.
/// e.g., "Blinding", "Bundle Pulling", "Inspection" for Heat Exchangers
model StandardActivityType {
  id                  String   @id @default(uuid()) @db.Uuid
  organization_id     String?  @db.Uuid  /// null = platform-level
  equipment_type_id   String   @db.Uuid  /// FK to EquipmentType
  name                String              /// "Blinding", "Bundle Pulling"
  code                String              /// "BLIND", "BPULL", "INSP"
  description         String?
  is_mandatory        Boolean  @default(true)  /// Must this activity exist for the equipment type?
  typical_duration_hrs Float?   /// Typical duration for planning reference
  sort_order          Int      @default(0)
  is_active           Boolean  @default(true)
  created_at          DateTime @default(now())
  updated_at          DateTime @updatedAt
  
  equipment_type      EquipmentType @relation(fields: [equipment_type_id], references: [id])
  
  @@unique([equipment_type_id, code])
  @@index([organization_id, equipment_type_id])
  @@map("standard_activity_types")
}
```

**Plus** one new field on Activity:

```prisma
model Activity {
  // ... existing fields ...
  standard_activity_type_id  String?  @db.Uuid  /// FK to StandardActivityType
  standard_activity_type     StandardActivityType? @relation(...)
}
```

**Plus** normalize `Asset.asset_type` to FK:

```prisma
model Asset {
  // ... existing fields ...
  equipment_type_id  String?  @db.Uuid  /// FK to EquipmentType (replaces free-text asset_type)
  equipment_type     EquipmentType? @relation(...)
}
```

### Aggregation Algorithm (Conceptual)

```
For a given event and standard_activity_type:

1. Find all activities where:
   - event_id = target_event
   - standard_activity_type_id = target_type
   - deleted_at IS NULL
   - status != 'cancelled'

2. Aggregate:
   - total_applicable = COUNT(*)
   - completed = COUNT(WHERE status = 'completed' OR progress_percent = 100)
   - in_progress = COUNT(WHERE progress_percent > 0 AND progress_percent < 100)
   - not_started = COUNT(WHERE progress_percent = 0 AND status = 'not_started')
   - balance = total_applicable - completed
   - completion_pct = completed / total_applicable × 100

3. Group by equipment_type for drill-down:
   Equipment Type | Total | Complete | In Progress | Not Started | Balance | %
   Heat Exchanger |   50  |    15    |      10     |     25      |   35    | 30%
   Vessel         |   30  |     5    |       8     |     17      |   25    | 17%
   Column         |   20  |     0    |       3     |     17      |   20    |  0%
```

### Equipment-Specific Applicability

Not all standard activities apply to all instances of an equipment type. Applicability is determined by:

1. **Template selection**: When a workpack is created from a template, only the template's activities become instances
2. **Manual override**: Planner can add/remove activities
3. **`is_mandatory` flag**: Some standard activities (e.g., "Blinding") are always applicable for safety

The `standard_activity_type_id` on Activity records which standard type this instance represents. If it's null, the activity is a custom/non-standard activity and excluded from identical-activity analysis.

### Data Population Strategy

For existing data without `standard_activity_type_id`:
1. **Template-created activities**: Can be backfilled from `workpack_template_activities.activity_code` → `StandardActivityType.code`
2. **Free-text activities**: Require fuzzy matching or manual classification
3. **New activities**: Should be classified at creation time via template or activity library
