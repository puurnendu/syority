## Reporting Hierarchy

```
Level 1: SHUTDOWN / EVENT
  ├── Total Workpacks (count, % by status)
  ├── Total Activities (count, duration-weighted %)
  ├── QA Holds (pending/cleared/total)
  ├── Constraints (open/closed/total)
  └── Safety (incidents/permits)

Level 2: EQUIPMENT / ASSET
  ├── Equipment Type / Tag
  ├── Workpack (WO#, title, status, progress)
  ├── Critical Path Activities
  ├── QA Hold Status
  └── Execution Condition

Level 3: WORKPACK
  ├── Execution Phase Breakdown (PreSD/OP/SD/IR/PostSD)
  ├── Activity Family Breakdown (PREP/ISO/CLEAN/INSP/REPAIR/...)
  ├── QA Status (Hold Points cleared/pending)
  ├── Resource Utilization
  └── Material Status

Level 4: ACTIVITY
  ├── Status, Progress %, Duration, Float
  ├── Phase (Window), Family, Code
  ├── Hold Point (type, cleared?, aging)
  ├── Resource (assigned, actual)
  └── Constraints
```

## QA in Management Reporting

### Problem: QA Activity Duration Distortion

**[FACT]** In the HMEL corpus, QA Hold Points range from 1-6 hours (inspector effort), while major activities range from 12-240 hours (actual work).

If QA activities contribute equally to progress:
- A 2-hour inspection counts the same as a 160-hour retubing activity
- Progress jumps artificially when multiple short inspections complete
- Management sees misleading progress percentages

### Solution: Three-Track Progress Model

> **[RECOMMENDATION]** Report three separate progress metrics:

| Metric | Formula | What It Measures |
|---|---|---|
| **Execution Progress** | Σ(non-QA activities × duration × progress%) / Σ(non-QA durations) | How much WORK is done |
| **QA Progress** | QA Hold Points cleared / Total Hold Points | How much INSPECTION is done |
| **Overall Progress** | Duration-weighted across ALL activities | P6-compatible overall metric |

### Duration-Weighted Progress (Recommended Default)

```
Overall Progress = Σ(activity.progress_percent × activity.duration_hours)
                   ÷ Σ(activity.duration_hours)
```

This naturally handles the QA duration problem:
- 2-hour inspection at 100% contributes 2.0 weighted-hours
- 160-hour retubing at 50% contributes 80.0 weighted-hours
- Progress is dominated by ACTUAL work volume, not activity count

### Management Dashboard KPIs

| KPI | Source | Calculation |
|---|---|---|
| Shutdown Progress | All activities | Duration-weighted progress |
| Phase Progress (PreSD/OP/SD/IR/PostSD) | Activities filtered by window | Duration-weighted per phase |
| QA Holds Cleared | qa_clearance_records | Count cleared / total hold points |
| QA Holds Aging | Hold points without clearance > 24h | Count where age > threshold |
| Critical Path Status | Activities where is_critical = true | Count delayed/on-track |
| Constraint Resolution | ConstraintLog | Open vs closed |
| Material Readiness | workpack_material_lines | Issued vs required |
| Blind Status | Blind model | Inserted vs removed |
