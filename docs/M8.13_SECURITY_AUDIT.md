# M8.13 Security Audit

## Tenant Isolation Verification

### Existing API Security Patterns

All existing dashboards use the `withTenantGuard` + `guardApi` pattern:

| Route | Guard | Permission | Org Isolation |
|-------|-------|-----------|---------------|
| `/api/dashboard/portfolio-stats` | `withTenantGuard` | `workpacks.view` | ✅ `orgScope(session)` |
| `/api/events/[eventId]/execution` | `withTenantGuard` | `nav.schedule` | ✅ `orgId` from session |
| `/api/events/[eventId]/evm/*` | `withTenantGuard` | `nav.schedule` | ✅ `orgId` param enforcement |
| `/api/events/[eventId]/materials/*` | `withTenantGuard` | `nav.schedule` | ✅ `orgId` from session |
| `/api/events/[eventId]/scope-changes/*` | `withTenantGuard` | `nav.schedule` | ✅ `orgId` from session |

### Security Findings

| Finding | Severity | Location | Risk |
|---------|----------|----------|------|
| All M8.12 material APIs properly guarded | SAFE | `app/api/events/[eventId]/materials/*` | None |
| portfolio-stats uses `orgScope(session).orgId` | SAFE | L10 | None |
| EvmSnapshotService enforces `organization_id` | SAFE | All queries | None |
| ScheduleHealthService scopes to `eventId + orgId` | SAFE | All queries | None |
| Report providers receive `ctx.organizationId` | SAFE | `ProviderContext` | None |

### Potential Risk Areas for M8.13

| Risk | Description | Mitigation |
|------|-------------|-----------|
| Cross-event leakage in aggregation | Progress aggregation queries must filter by `event_id` | Enforce `event_id` in all M8.13 service queries |
| Identical activity analysis across events | Could inadvertently aggregate across events | Require explicit `event_id` parameter |
| Executive dashboard multi-event view | If supported, must filter by org-owned events only | Use `organization_id` join |
| Cached KPI data | If caching introduced, must be keyed by `org_id + event_id` | Cache key includes tenant |

### M8.13 Security Requirements

1. All new API routes MUST use `withTenantGuard`
2. All new API routes MUST use `guardApi` with appropriate permission
3. All Prisma queries MUST include `organization_id` filter
4. All event-scoped queries MUST include `event_id` filter
5. Any caching MUST be keyed by `organization_id + event_id`
6. No cross-tenant data in aggregation queries
7. No cross-event data unless explicitly multi-event (org-level summary)
