# M8.1 — Event Context Audit & Model Inspection

This audit maps the current relationship between the `Event` (Shutdown) model and downstream operational features in the SYORITY codebase.

---

## 1. Database Schema Relationship Map (`prisma/schema.prisma`)

```
Organization (id: UUID)
 └── Site (id: UUID)
      └── Event / Shutdown (id: UUID, code: String, name: String, status: String)
           ├── EventMilestone (event_id)
           ├── EventUnit (event_id, unit_id)
           ├── EventSystem (event_id, system_id)
           ├── WbsNode (event_id)
           ├── ShutdownScope (event_id)
           ├── Workpack (event_id, site_id, organization_id)
           │    ├── Activity (workpack_id, event_id)
           │    ├── WorkpackMaterial (workpack_id)
           │    ├── JointIntegrityItem (workpack_id)
           │    ├── Blind (workpack_id)
           │    ├── Constraint (workpack_id)
           │    └── PunchListItem (workpack_id)
           ├── SafetyLog (event_id, site_id, organization_id)
           ├── SafetyIncident (event_id, site_id, organization_id)
           └── SafetyPhoto (event_id)
```

## 3. Key Risks in Current Implementation

1.  **Context Loss During Cross-Page Navigation:**
    *   If a turnaround planner is working on `TA-2026` inside `/events/45830d69.../scope` and clicks *"Workpacks"* or *"Schedule"* in the sidebar, they are redirected to `/workpacks` or `/schedule`, where the `event_id` is lost.
2.  **Accidental Historical Data Blending:**
    *   Because `/api/activities` and `/api/workpacks` default to returning all records when `event_id` is not provided, planners might see closed tasks from `TA-2022` mixed into active views.
3.  **No Authoritative Active Shutdown Context:**
    *   There is no single global store (cookie/session/context) holding `active_event_id`, forcing components to inspect URL strings or fall back to organization-wide queries.

---

## 4. Architectural Solution

Establish a unified **Dual-Layer Active Shutdown Context Engine**:
1.  **HTTP Cookie (`active_event_id`):** Seamlessly passed to all Server Components and API route handlers.
2.  **React Context (`ActiveShutdownContext`):** Reactively updates all client components, top-bar badges, and navigation links.
3.  **Global Selector Dropdown:** Always visible in the authenticated shell header showing `[Site Name] | [Active Shutdown ▼]`.
