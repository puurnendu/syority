# M8.6 ASSET REGISTER — ARCHITECTURE AUDIT

## 1. Executive Summary

The SYORITY codebase already possesses a **substantial Asset Register foundation** with 201 Prisma models spanning equipment hierarchy, document management, AI extraction, and planning. The existing `Asset` model is well-structured with 40+ typed columns, a complete Plant→Unit→System→Asset hierarchy, and a mature Digital Plant Builder (M7.1) with planner-reviewed AI extraction.

**Verdict: C — EXISTING COMPONENTS SHOULD BE EXTENDED**

The existing Asset model, Digital Plant Builder, and document architecture form a solid base. However, they must be elevated from a "planning support tool" to the **Primary Master Layer** that all other modules reference. Key gaps include: no Corrosion Loop dimension, no equipment-type-specific configurable attributes, no field-level provenance/versioning on Asset technical data, no maintenance workflow model, and no derived register architecture.

### 4.1 Workpack-Level `equipment_technical_data` (JSON)

**Location:** `Workpack.equipment_technical_data` ([L112](file:///C:/DEV/STO/prisma/schema.prisma#L112))

This is a **JSON blob** stored directly on the Workpack. It is populated by:
1. AI extraction from drawings via [`/api/workpacks/[id]/extract-technical-data`](file:///C:/DEV/STO/app/api/workpacks/%5Bid%5D/extract-technical-data/route.ts)

**Structure (Heat Exchanger focused):**
```json
{
  "equipment": { "name", "type", "tema_designation", "manufacturer" },
  "dimensions": { "shell_id_mm", "overall_length_mm", "tube_length_mm", ... },
  "tube_bundle": { "total_tubes", "tube_od_mm", ... },
  "shell_side": { "medium", "design_pressure_kg_cm2", ... },
  "tube_side": { ... },
  "materials": { ... },
  "nozzles": { ... },
  "design_codes": [...]
}
```

> [!CAUTION]
> **This is the PRIMARY DUPLICATE.** Equipment technical data is stored on each Workpack copy, not on the Asset itself. Every new Workpack for the same equipment re-extracts or re-enters the data independently.

## 17. Proposed Target Architecture

```
                     ┌───────────────────────┐
                     │     ASSET REGISTER     │
                     │  PRIMARY MASTER LAYER  │
                     │                        │
                     │  Asset (existing)       │
                     │  + AssetAttribute       │
                     │  + AssetAttributeVer    │
                     │  + CorrosionLoop        │
                     │  + parent_asset_id      │
                     └───────────┬─────────────┘
                                 │
          ┌──────────────────────┼──────────────────────┐
          │                      │                      │
          ▼                      ▼                      ▼
     WORKPACK                  AIM              MAINTENANCE
     PLANNING              INTEGRITY              WORKFLOW
          │                      │                      │
    ┌─────┴─────┐          ┌─────┴─────┐         ┌─────┴─────┐
    │Activity    │          │(Future)   │         │(Future)    │
    │Resources   │          │RBI/Risk   │         │MaintReq    │
    │Schedule    │          │Inspection │         │Observation │
    │UDF (exec)  │          │CML/TML    │         │Recommend.  │
    │Execution   │          │Findings   │         │SAP Link    │
    └─────┬─────┘          │FFS        │         └─────┬─────┘
          │                └─────┬─────┘               │
          └──────────────────────┼──────────────────────┘
                                 ▼
                     ┌───────────────────────┐
                     │   DERIVED REGISTERS    │
                     │  Blind Register        │
                     │  Nozzle Register       │
                     │  Flange Register       │
                     └───────────┬─────────────┘
                                 ▼
                     ┌───────────────────────┐
                     │  DASHBOARD / DPR       │
                     │  REPORTING / EXPORT    │
                     └───────────────────────┘
```

### Key Design Decisions

1. **Extend `Asset`, do not replace it.** Add `parent_asset_id`, `area_id`, `corrosion_loop_id`.
2. **Add `AssetAttribute` model** (following the proven UDF pattern): Definition → Value with field-level provenance (source doc, confidence, verification status, verified_by).
3. **Add `AssetAttributeVersion`** for tracking historical snapshots when verified data changes.
4. **Add `CorrosionLoop`** as an independent dimension (not child of System).
5. **Migrate `equipment_technical_data`** from Workpack JSON → Asset Register attributes.
6. **Workpack references Asset version** via snapshot at issue time.

## 18. Migration Considerations

| Step | Risk | Mitigation |
|------|------|-----------|
| Add new columns to `Asset` | Low — nullable additions | No data loss |
| Create `AssetAttribute` + `AssetAttributeVersion` | Low — new tables | No existing data affected |
| Migrate `equipment_technical_data` → Asset attributes | Medium — existing JSON data must be parsed | Write migration script, keep JSON as fallback |
| Redirect `extract-technical-data` → Asset Register | Medium — changes consumer behavior | Feature flag, parallel write period |
| Unify `system_blinds` and `Blind` | High — two separate models with different scopes | Phase 3, careful data reconciliation |

- Missing: maintenance-specific fields (observation type, SAP work order reference, approval workflow, communication thread)
- **Recommendation:** Create a new `MaintenanceRequest` model that links to Asset and optionally to EngineeringIssue, rather than overloading EngineeringIssue

## Final Verdict

### C — EXISTING COMPONENTS SHOULD BE EXTENDED

The codebase already has:
- A rich 40+ column `Asset` model with hierarchy
- A functional Asset Register UI with hierarchy tree and detail tabs
- A mature AI extraction pipeline (Digital Plant Builder) with planner review
- A proven UDF/attribute pattern for configurable fields
- Document management with revision tracking and M:M asset linkage

**Do not replace these.** Extend them to become the Primary Master Layer by:
1. Adding equipment-type-specific configurable attributes with field-level provenance
2. Adding Corrosion Loop and parent asset dimensions
3. Migrating `equipment_technical_data` from Workpack to Asset
4. Adding versioning/snapshots for Asset technical data
5. Building derived registers on top of existing `Blind`, `nozzles`, and `joint_masters`
