# M8.12 — CPM Integration Specification

**Status**: LOCKED  
**Date**: 2026-09-01

## Core Principle

**scheduleEngine.ts is PROTECTED and FROZEN.** M8.12 must integrate material constraints without modifying the CPM engine.

---

## Integration Architecture

### Option Selected: Synthetic Constraint Injection (Pre-CPM)

Material constraints are injected into the CPM calculation as **adjusted planned_start dates** on activities that have material dependencies. The CPM engine's existing forward pass naturally respects `planned_start` as a floor for activities with no predecessors.

For activities WITH predecessors, the material constraint date is expressed as:

```
Effective_Planned_Start = max(Activity.planned_start, Material_Constraint_Date)
```

This adjusted value is passed to the CPM engine in the `ScheduleActivityInput.planned_start` field.

### Why NOT Synthetic Predecessors

Creating virtual "material milestone" activities would:
- Pollute the activity database with phantom records
- Complicate the activity hierarchy and WBS
- Require cleanup/filtering in all reports and dashboards

### Why NOT Post-CPM Adjustment

Adjusting Early Start AFTER CPM runs would:
- Lose transitive propagation (downstream activities wouldn't shift)
- Produce inconsistent total float calculations
- Break critical path identification

---

## Integration Boundary

### New Service: `MaterialScheduleIntegrationService`

This service sits BETWEEN the data layer and the CPM engine call:

```
1. Load activities from database
2. Load material constraints for those activities
3. For each activity with a binding material constraint:
   - Set planned_start = max(original_planned_start, constraint_date)
4. Pass adjusted activities to calculateSchedule()
5. CPM engine calculates normally
6. Return results (Early Start now respects material constraints)
```

### Existing Call Sites

The CPM engine is called from:
1. `/api/events/[eventId]/schedule/calculate` — Live schedule calculation
2. `ScenarioCalculationService.calculate()` — Scenario calculation

Both call sites must be updated to inject material constraints before calling `calculateSchedule()`.

## Material Constraint Date Calculation

```
Material_Constraint_Date(activity) = 
  MAX(ETA) across all material requirements for the activity
  WHERE quantity_available + quantity_on_order < quantity_required

If all materials are available:
  Material_Constraint_Date = NULL (no constraint)

If some materials have no ETA:
  Material_Constraint_Date = INDETERMINATE (flag for human review)
```

---

## Deterministic Rule

```
Activity Effective Early Start = max(
  CPM_Early_Start (from predecessor logic),
  Material_Constraint_Date (from supply chain),
  Resource_Constraint_Date (from M8.8, if applicable)
)
```

This is implemented by adjusting `planned_start` before CPM runs, so:
- CPM naturally computes `early_start >= planned_start`
- The material constraint propagates through the network
- Total float and critical path reflect material delays
