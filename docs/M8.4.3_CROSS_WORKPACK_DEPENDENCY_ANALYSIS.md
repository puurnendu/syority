## RECOMMENDATION

> **[RECOMMENDATION]** SYORITY should support cross-workpack relationships but should NOT require them from the workpack template.

### Implementation Approach

1. **ActivityRelationship model already supports cross-WP links** — predecessor_id and successor_id can reference activities from different workpacks
2. **Template-level logic links should remain intra-template** — cross-WP dependencies are created at the EVENT/SCHEDULE level
3. **P6 handles cross-WP scheduling** — SYORITY exports activities to P6, where the scheduler creates inter-workpack dependencies
4. **Event-level milestones** (e.g., "FCC Unit Isolation Complete") can serve as shared predecessors

### SYORITY Schema Compatibility

**[FACT]** ActivityRelationship has no workpack constraint — predecessor_id and successor_id are both Activity UUIDs. Cross-WP relationships are already structurally supported.

**[RECOMMENDATION]** No schema change needed. Cross-WP dependencies should be created via the scheduling interface, not the template system.
