# M8.7 Phase 2F.3 - Leveling Quality & Deterministic Rules

## Overview
Phase 2F introduces a hardened, deterministic leveling heuristic that prevents schedule volatility and preserves planner expectations. 

## Eligibility Filter
Before an activity is even considered for delay, it must pass:
`!is_critical && total_float_days > 0`

## Deterministic Scoring
Candidates are scored as follows:
`score = -(total_float_days * 10)`

If an activity is **Near-Critical** (`total_float_days <= 2`), we apply a strong protection penalty:
`score += 1000`

### Priority Hierarchy (Enforced by Sorting)
The candidate array is sorted using `Score ASC`. In the event of a tie, `Activity ID ASC` breaks the tie to guarantee mathematical determinism.
1. **Critical/Zero-Float**: Hard Excluded
2. **Near-Critical**: Heavily Penalized (Moved Last)
3. **High Float**: Preferred candidates (Lowest Negative Scores)

## Result
Given identical inputs, the engine will ALWAYS yield identical leveling recommendations. Project end dates are never extended to resolve resource constraints automatically.
