# M8.7 Phase 2D.1 — Resource Planning Schema Enhancements (Walkthrough)

## 1. Goal Description
The objective of this phase was to implement the foundational schema for Resource Planning in M8.7 (Phase 2D.1) while strictly adhering to architectural invariants: tenant isolation via `organization_id`, zero duplication of task/shift/equipment tables, and positioning `Event` as the authoritative shutdown entity.

## 2. Implemented Schema Enhancements

### New Models (`prisma/schema.prisma`)
Two new models were added to the schema:

1. **`ShiftDefinition`**
   - **Purpose:** Defines shift patterns (e.g., "Day Shift", "Night Shift") with `start_time` and `end_time`.
   - **Associations:** Owned by `Event` and `Organization`.
   - **Constraints:** Enforces `@@unique([event_id, shift_name])`.

2. **`ResourceCapacity`**
   - **Purpose:** Tracks maximum time-phased supply (capacity) of a specific resource per day and shift. Accommodates both manpower and equipment with a `Decimal` capacity limit.
   - **Associations:** Belongs to `Event`, `Organization`, `ResourceType`, `Contractor` (optional), and `ShiftDefinition` (optional).
   - **Constraints:** Ensures no overlapping capacity buckets via `@@unique([event_id, resource_type_id, contractor_id, shift_id, target_date], name: "unique_capacity_bucket")`.

### Relationship Back-References
Back-references for the two new models were added to existing parent models to maintain bidirectional Prisma mapping:
- `Organization` (`shift_definitions`, `resource_capacities`)
- `Contractor` (`resource_capacities`)
- `ResourceType` (`resource_capacities`)
