## Changes Made

### Fix 1 — Event Create Form
**File:** `app/(dashboard)/events/new/page.tsx`
- Fixed API URL: `/api/admin/sites` → `/api/settings/sites` (root cause of the UUID fallback appearing)
- Removed `type="text"` UUID fallback entirely
- When no sites load: disabled `<select>` with "No sites available — contact admin"
- Auto-selects when only 1 site exists

### Fix 2 — Asset Import Page
**File:** `app/(dashboard)/asset-register/import/page.tsx`
- Replaced `<input type="text" placeholder="UUID of Site">` with `<select>` dropdown
- Replaced `<input type="text" placeholder="UUID of Unit">` with cascading `<select>` dropdown
- Site loads from `/api/settings/sites` on mount
- Unit loads from `/api/hierarchy?site_id=X` when site is selected
- Auto-selects when only 1 option in either dropdown
- Labels changed: "Site ID" → "Site", "Unit ID" → "Unit"

### Fix 3 — Events API UUID Validation
**File:** `app/api/events/route.ts`
- Imported `isUuid` from `@/lib/uuid`
- Added UUID format validation for `site_id` (required), `calendar_id`, `discipline_id`, `parent_event_id` (optional)
- Invalid UUIDs now return `400 Bad Request` with clear message instead of Prisma `500`

### Fix 4 — Tenant-Scoped Event Code Uniqueness
**File:** `src/core/planning/EventPlanningService.ts`
- Added `findFirst` check before `create`: rejects if non-deleted event with same `(organization_id, code)` exists
- Error message: `Event code "X" already exists in this organization`
- Application-level enforcement — no schema migration required
