# M8.5 — Reporting Model

## Architecture

```
Activity State / UDF Value / Quantity
        ↓
Provider (report-engine/providers/*.ts)
        ↓
WidgetDataService (cache + batch)
        ↓
OIS Dashboard Widget / Report Section
        ↓
Web Dashboard / PDF DPR
```

## Metric → Widget Separation

| Layer | Model | Purpose | Example |
|---|---|---|---|
| Metric Definition | `bre_kpi_definitions` | "What do we measure?" | "Blinding Completed %" |
| Formula | `bre_formulas` | How to compute | `completed / total * 100` |
| Data Provider | `report_data_providers` | Where data comes from | `execution.activity_status` |
| Widget Definition | `ois_widget_definitions` | Reusable widget type | "KPI Card", "Status Table" |
| Dashboard Widget | `ois_dashboard_widgets` | Placed widget instance | Position, config, thresholds |

## DPR Column Mapping

Every DPR column maps to existing data — NO separate DPR model:

| DPR Column | Data Source | Query |
|---|---|---|
| Scope (Total) | `COUNT(activities) WHERE activity_code LIKE 'ISO.%'` | Activity count |
| Handover | `COUNT(activities) WHERE activity_code = 'HP.HANDOVER' AND status = 'completed'` | Activity status |
| Blinding | `COUNT(activities) WHERE activity_code = 'ISO.BLINDING' AND status = 'completed'` | Activity status |
| Bundle Pullout | `COUNT(activities) WHERE activity_code = 'DISMANTLE.TB_REMOVAL' AND status = 'completed'` | Activity status |
| Pre-Inspection | `COUNT(activities) WHERE activity_code LIKE 'INSP.%' AND status = 'completed'` | Activity status |
| Hydrojetting | `COUNT(activities) WHERE activity_code = 'CLEAN.TB_HYDROJETTING' AND status = 'completed'` | Activity status |
| Welding Quantity | `SUM(udf_values.value_number) WHERE udf_code = 'WELD_QTY'` | UDF rollup |
| Painting Area | `SUM(udf_values.value_number) WHERE udf_code = 'PAINT_AREA'` | UDF rollup |

## Hierarchical Aggregation

Already implemented in `RollupEngine.computeEventRollups()`:

```
Activity → Workpack → System → Unit → Event (Shutdown)
```

Supports: SUM, AVG, MIN, MAX, COUNT

Used by `HierarchicalUDFRollupProvider` and `UDFQuantitySummaryProvider`.

## Management Levels (configurable via dashboards)

| Level | Dashboard Scope | Widget Types |
|---|---|---|
| Top Management | KPI cards, S-Curve, achievement % | `kpi_card`, `s_curve`, `trend_chart` |
| Middle Management | Unit progress, equipment status tables | `pivot_table`, `progress_bar`, `status_table` |
| Planning | Activity details, critical path, look-ahead | `activity_table`, `gantt`, `resource_histogram` |

All three levels query the SAME underlying data through different `provider_params` and `visualization_config`.

## Status Table Widget (configurable pivot)

`ois_dashboard_widgets.visualization_config` JSON:

```json
{
  "type": "pivot_table",
  "rows": ["unit_name"],
  "columns": ["equipment_type"],
  "measures": [
    { "key": "scope", "agg": "COUNT", "filter": {} },
    { "key": "completed", "agg": "COUNT", "filter": { "status": "completed" } },
    { "key": "in_progress", "agg": "COUNT", "filter": { "status": "in_progress" } },
    { "key": "balance", "formula": "scope - completed - in_progress" }
  ]
}
```

## Web ↔ PDF Parity

Both web dashboards and PDF reports use the same data providers:

```
ois_widget_definitions.provider_key  ←→  report_data_providers.key
```

The report builder renders the same data into PDF layout via `report_sections`.
