# M8.4.5 — Quantity Progress Model

> **M8.4.5** — Generated: 2026-08-15T09:50:59.322Z
> Evidence Source: P6 XER (510-512-FCCPRU-R0-2.xer, 8.5MB), HMEL Workpacks, iPlan Source
> Classification: FACT | INFERENCE | RECOMMENDATION | UNKNOWN

## Problem
A single progress percentage is insufficient for quantity-based activities.

## Recommended Architecture

**[RECOMMENDATION]** Option B: ProgressLog with quantity_actual

```
ProgressLog {
  activity_id    FK
  log_date       Date
  progress_pct   Decimal
  quantity_actual Decimal  // NEW: cumulative actual quantity
  quantity_unit   String   // NEW: m³, m², inch-dia
  manhours_actual Decimal
  notes          String
}
```

### Why ProgressLog?
- ✅ Time-series history (daily/shift reporting)
- ✅ Audit trail
- ✅ Cumulative curves for management reporting
- ✅ Correction/rollback possible
- ✅ Equipment-level aggregation via Activity→Workpack→Equipment

### Progress Calculation
```
If quantity-based:
  Progress = Latest(quantity_actual) / Planned(ActivityUdfValue.value_number)

If duration-based:
  Progress = Σ(activity.progress × activity.duration) / Σ(activity.duration)
```
