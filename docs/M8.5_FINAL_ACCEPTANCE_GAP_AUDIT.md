## 3. DEEP FORENSIC INVESTIGATION BY SECTION

### Section 1: Dashboard & DPR Configuration Architecture
* **Finding:** The database contains 11 OIS (Operations Information System) tables (`ois_dashboard_definitions`, `ois_widget_definitions`, `ois_dashboard_pages`, `ois_dashboard_widgets`, `ois_tv_sessions`, etc.) and 14 Report Builder tables (`report_definitions`, `report_sections`, `report_layouts`, etc.).
* **Persistence:** `DashboardService.ts` and `ReportService.ts` provide full multi-page dashboard CRUD, grid layout (`grid_x`, `grid_y`, `grid_w`, `grid_h`), widget bindings, and category filtering.
* **Audit State:** Tables currently have 0 rows (unseeded). Visual configuration of pre-built role dashboards (Top Management KPI, Middle Management Equipment Table, Planning Schedule) is part of M9 (Reporting & Analytics).
* **Classification:** **FUTURE FEATURE / M9 & NON-BLOCKER FOR M8.5**.

### Section 2: DPR Execution-to-Reporting Flow
* **Model Validation:** `Execution Data → UDF / Activity Code / Equipment → Aggregation → Configurable Widget → DPR`.
* **Validation:** Verified that UDF values are strictly optional on activities. Activity Code selection standardizes creation, auto-populating metadata and resources. UDFs serve reporting, filtering, and aggregation without cluttering non-quantity activities.
* **Classification:** **IMPLEMENTED & ARCHITECTURALLY SOUND**.

### Section 3: Lightweight Management Metric
* **Philosophy:** Management dashboards must NOT force micro-schedule start/finish times or resource details onto executive views.
* **Validation:** Tested lightweight aggregation:
  $$\text{Achievement} = \frac{\text{Completed Workpacks}}{\text{Planned Workpacks by Cutoff}} \times 100$$
  * Planned: 30
  * Completed: 25
  * Balance: 5
  * Achievement: 83.33%
* **Classification:** **IMPLEMENTED & RUNTIME PROVEN**.

### Section 4: Equipment Status Table (DPR Middle Management)

### Section 5: Activity Number Architecture
* **Database Constraint:** `CREATE UNIQUE INDEX "Activity_organization_id_activity_number_key" ON "Activity" (organization_id, activity_number)`.
* **Identified Defect:** `TemplateLibraryService.ts` line 615 sets `activity_number: a.activity_code`. Because `activity_code` is a domain category (e.g., `PREP.SCAFFOLDING`), instantiating multiple workpacks with the same template in the same organization causes a unique constraint violation.
* **Architectural Recommendation:**
  1. `activity_code` must remain the domain code linked via `activity_library_id`.
  2. `activity_number` should be generated as an instance identifier (e.g., `${workpack_number}-${sequence_number * 10}` or `ACT-${sequence}`).
  3. The database constraint should ideally be scoped to `(workpack_id, sequence_number)` rather than global `(organization_id, activity_number)`.
* **Classification:** **M8.5 ARCHITECTURAL DEFECT (P1 NON-BLOCKER FOR M8.5 ACCEPTANCE; SCHEDULED FOR M8.6 REVISION)**.

* **Classification:** **P1 GAP (NON-BLOCKER FOR NORMAL HAPPY-PATH EXECUTION, SCHEDULED FOR M8.6 WRAP)**.
