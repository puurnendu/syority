## Architecture Recommendation

**[RECOMMENDATION]** Use the existing ActivityUdfValue for PLANNED quantities. Use ProgressLog for ACTUAL quantities over time.

### Planned Quantity
```
ActivityUdfValue {
  activity_id    → Activity
  udf_id         → UdfDefinition  
  value_number   Decimal  // Planner enters: 4,500
  value_text     String   // Optional notes
}
```

### Actual Quantity (Time-Series)
```
ProgressLog {
  activity_id      → Activity
  log_date         Date
  progress_percent Decimal  // Overall %
  quantity_actual  Decimal  // NEW: cumulative actual (e.g., 3,200 m³)
  quantity_unit    String   // NEW: unit (m³, m², inch-dia)
  manhours_actual  Decimal  // Actual manhours
  notes            String
}
```

### Why ProgressLog for Actuals?
1. **[FACT]** iPlan does not track actual quantities — workpack quantities are planning-only fields
2. **[FACT]** P6 does not receive workpack quantities — they are not exported
3. **[RECOMMENDATION]** Therefore actual quantity tracking is a SYORITY-NATIVE capability that goes beyond both iPlan and P6
4. ProgressLog provides time-series history for cumulative curves and daily reporting
