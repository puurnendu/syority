# M8.5 — Export Model

## Architecture

```
SYORITY Schedule (Activity + ActivityRelationship + UDF)
        ↓
Export Route (app/api/export/generate/route.ts)
        ↓
Format-specific builder functions
        ↓
 ┌──────┬──────────┬──────────────┐
 ↓      ↓          ↓              ↓
CSV   Excel    P6 XML/XER    MS Project XML
```

## Export Data Query Enhancement

Current query:
```typescript
prisma.workpack.findMany({
  where: { id: { in: body.workpackIds } },
  include: { activities: true },
});
```

Enhanced query:
```typescript
prisma.workpack.findMany({
  where: { id: { in: body.workpackIds } },
  include: {
    activities: {
      include: {
        predecessors: {
          include: { predecessor: { select: { activity_number: true, id: true } } }
        },
        discipline: { select: { name: true, code: true } },
      },
    },
    asset: { select: { tag_number: true, name: true, description: true } },
    unit: {
      include: { plant: { select: { name: true } } },
      select: { name: true },
    },
    contractor: { select: { name: true } },
  },
});
```

## P6 Independence Verification

The export is a ONE-WAY adapter:

```
SYORITY models → Export builder → P6/MSP format
```

No P6 format structures are stored in SYORITY.
No P6 IDs are required to create activities.
`p6_object_id` and `p6_activity_id` fields on Activity are nullable legacy fields.
