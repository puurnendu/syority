# M8.2 — Security & IDOR Verification Report

This report documents the security audit and IDOR (Insecure Direct Object Reference) penetration tests performed on the **Bulk Activity Mutation Engine** (`POST /api/activities/bulk`) and active shutdown context boundaries.

---

## 1. Security Test Matrix & Verification

| Test Code | Target Scenario | Execution & Attack Vector | Expected Result | Actual Result | Verdict |
|---|---|---|---|---|---|
| **SEC-01** | **Tenant A Authorized Creation** | Tenant A bulk creates activities under owned Event A | HTTP 200 Created | **HTTP 200** | **PASS** |
| **SEC-02** | **Cross-Tenant IDOR (Create)** | Tenant B attempts to inject activities into Tenant A's Event A | Blocked (404/403) | **HTTP 404** | **PASS** |
| **SEC-03** | **Cross-Tenant IDOR (Update)** | Tenant B attempts to modify Tenant A's activity description | Blocked (404/403) | **HTTP 404** | **PASS** |
| **SEC-04** | **Cross-Tenant IDOR (Delete)** | Tenant B attempts to soft-delete Tenant A's activity | Blocked (404/403) | **HTTP 404** | **PASS** |
| **SEC-05** | **Malformed Event UUID** | Request with `event_id: "not-a-valid-uuid"` | 400 Bad Request (0 unhandled 500s) | **HTTP 400** | **PASS** |
| **SEC-06** | **Non-Existent Event UUID** | Request with random unassigned UUID | 404 Not Found (0 unhandled 500s) | **HTTP 404** | **PASS** |
| **SEC-07** | **Payload Validation** | Create activity without mandatory `description` | 422 Unprocessable Entity | **HTTP 422** | **PASS** |

---

## 2. Defensive Controls Implemented

1.  **Multi-Tenant Query Scoping:** Every database query in `POST /api/activities/bulk` validates both `organization_id: session.organization_id` and `event_id: activeEventId`.
2.  **Transaction Atomicity:** All creates, updates, and deletes run within `prisma.$transaction`. Any single unexpected failure rolls back the entire batch without database corruption.
3.  **Strict Input Sanitation:** Non-UUID identifiers, empty strings, and negative durations are pre-validated before hitting the database.
