## Key Discoveries

### The Root Problem

The Prisma schema defines:
```
Activity.description  (not "name")
Activity.total_float  (not "total_float_days")
Activity.early_finish (not "early_end")
Activity.late_finish  (not "late_end")
```

The schedule engine (`scheduleEngine.ts`) outputs:
```
total_float_days  (different from Prisma's total_float)
early_finish      (matches Prisma)
late_finish       (matches Prisma)
```

The M8.7 services:
- Used `total_float_days` from the schedule engine output AS IF it were a Prisma field name
- Invented `name` (Activity uses `description`)
- Invented `early_end` and `late_end` in the Apply service (not matching either schema or engine)

This triple-mismatch was never caught because **no code was ever executed**.

### The Testing Gap

16 test scripts exist across M8.7 phases. None were ever executed. All "30/30 PASS" claims in acceptance documents are based on "Structural Verification" — reading source code and declaring it correct. The P0 defects prove this methodology was insufficient.

## What Is Working

Despite the P0 defects, significant engineering effort exists:

1. **Schema design** is sound — ResourceCapacity, ShiftDefinition, and ActivityResource models are correctly designed
2. **Capacity CRUD** works correctly with full FK validation and tenant isolation
3. **Shift management** works correctly
4. **Demand engine logic** is mostly correct (ignores planned_end, but the algorithm is sound)
5. **Leveling simulation logic** is architecturally correct — in-memory simulation with CPM recalculation per iteration
6. **Critical path protection** logic is correct (excludes critical and zero-float activities)
7. **ConflictService scoring** is deterministic and well-designed
8. **Tenant isolation** at the service level is comprehensive
9. **Legacy compatibility** is maintained — histogram files are untouched
10. **KPI, Forecast, and Risk** algorithms are logically sound (they just can't execute due to field name errors)

---

## Remediation Difficulty Assessment

The defects are concentrated in **field name mappings**, not in architectural design. The fix is surgical:

- **P0-001 through P0-004**: Find-and-replace across 7 files
- **P0-005 and P0-006**: Fix 5 API route files

Estimated remediation time: **2-3 hours** for a developer with database access.

The M8.7 architecture itself is well-designed. The failure mode was environmental — inability to run code against a database.
