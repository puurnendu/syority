# M8.10 EVM Formula Specification & Methodology

## Phase 0C — EVM Mathematical Definition
The following formulas are explicitly designed for STO industrial turnaround scheduling, heavily reliant on rapid, shift-by-shift execution.

### 1. Planned Value (PV) / Budgeted Cost of Work Scheduled (BCWS)
- **Formula:** `BAC * (Planned % Complete at Time T)`
- **Inputs:** `BaselineActivity.budgeted_cost` (BAC), Time-phased `BaselineActivity` date spread.
- **Time Basis:** Must be evaluated daily (or shiftly).
- **Baseline Basis:** Evaluated against the *Current Active* `ScheduleBaseline`.
- **Edge Cases:** If an activity lacks BAC, PV = 0 (or fallback to manhour PV).

### 2. Earned Value (EV) / Budgeted Cost of Work Performed (BCWP)
- **Formula:** `BAC * (Physical % Complete at Time T)`
- **Inputs:** `BaselineActivity.budgeted_cost`, `Activity.progress_percent`.
- **Source Model:** `Activity` (current progress) x `BaselineActivity` (snapshot BAC).
- **Edge Cases:** Cap EV at 100% of BAC even if progress logs exceed 100%.

### 3. Actual Cost (AC) / Actual Cost of Work Performed (ACWP)
- **Formula:** `Sum(ProgressLog.actual_cost)` OR `Activity.actual_cost`.
- **Inputs:** Shift logs.
- **Edge Cases:** Turnarounds often have delayed cost realization (timesheets lag by 24h). AC curve may lag EV curve artificially.

### 4. Cost Variance (CV) & Schedule Variance (SV)
- **CV Formula:** `EV - AC` (Positive = Under budget)
- **SV Formula:** `EV - PV` (Positive = Ahead of schedule)
- **Note:** EVM SV is in *dollars/hours*, not days.

### 5. Cost Performance Index (CPI) & Schedule Performance Index (SPI)
- **CPI Formula:** `EV / AC`
- **SPI Formula:** `EV / PV`
- **Zero-Division Behavior:** If AC = 0, CPI = 1.0 (or null). If PV = 0, SPI = 1.0 (or null).

### 6. Estimate At Completion (EAC)
- **Formula (Turnaround Default):** `AC + ((BAC - EV) / CPI)` (Assumes current cost performance will continue).
- **Alternative:** `AC + (BAC - EV)` (Assumes future work performed at budgeted rate). We recommend the CPI-driven model.

### 7. Estimate To Complete (ETC) & Variance at Completion (VAC)
- **ETC Formula:** `EAC - AC`
- **VAC Formula:** `BAC - EAC`

## Phase 0D — Earned Value Method Decision

### Analysis of Methods
1. **0/100:** EV is 0% until complete. Too conservative for long (e.g., 5-day) turnaround activities.
2. **50/50:** EV is 50% on start, 50% on finish. Can over-inflate EV during early execution phases.
3. **Physical % Complete:** Direct supervisor entry. Highly subjective but industry standard for piping/welding.
4. **Resource-Weighted:** (Actual Hours / Planned Hours). Dangerous in turnarounds (rewards inefficiency).

### Recommended Architecture: Hybrid Rules of Credit
- **Default:** **Physical % Complete** driven by `Activity.progress_percent`.
- **Future-Proofing:** The `Activity` model must eventually support a `rules_of_credit_id` tying physical progress to Quantities (e.g., 20% Fit up, 60% Weld, 20% NDE).
- **Current Action:** For M8.10 Phase 1, use direct `progress_percent` * BAC, maintaining schema simplicity while enabling EVM.
