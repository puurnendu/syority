# M8.13 — Progress Governance Rules

> **Version**: 1.0
> **Module**: M8.13 — Enterprise Progress Intelligence
> **Status**: ACTIVE — Production Governance

---

## 1. Authoritative Execution Progress Formula

### Primary Calculation — Duration-Weighted

```
Weighted Progress = Σ(duration_hours × progress_percent) / Σ(duration_hours)
```

Where:
- `duration_hours` = planned activity duration in hours
- `progress_percent` = current activity execution progress (0–100)
- Sum is over all **included** activities (see §4)

### Fallback — Simple Average

When `Σ(duration_hours) = 0` (all activities have null/zero duration):

```
Simple Average = Σ(progress_percent) / count(activities)
```

> **RULE**: Simple average is NEVER used when valid durations exist.

---

## 2. Completed Equivalent Hours

```
Completed Equivalent = Σ(duration_hours × progress_percent / 100)
```

This represents the **earned duration** — how many hours of work have been effectively completed.

---

## 3. Balance Equivalent Hours

```
Balance = Σ(duration_hours) − Completed Equivalent
```

This represents the **remaining duration** — how many hours of work remain.

---

## 4. Activity Inclusion Rules

### Included Activities
All activities where:
- `deleted_at IS NULL`
- `status ≠ 'cancelled'`

### Excluded Activities
- **Cancelled** activities (`status = 'cancelled'`) — excluded from both numerator and denominator
- **Deleted** activities (`deleted_at IS NOT NULL`) — excluded from all calculations

### Status-Based Interpretation
| Status | progress_percent | Interpretation |
|--------|-----------------|----------------|
| `not_started` | 0 | Contributes to denominator, 0 to numerator |
| `in_progress` / `in-progress` | 1–99 | Both numerator and denominator |
| `completed` / `complete` | 100 | Both numerator and denominator |
| `cancelled` | any | **Excluded entirely** |
| `scope-change-created` | 0 (default) | Included at 0% unless explicitly progressed |

---

## 5. Progress Boundaries

```
0 ≤ progress_percent ≤ 100
```

- Values < 0 are clamped to 0
- Values > 100 are clamped to 100
- `null` progress is treated as 0
- `null` duration is treated as 0 (activity excluded from weighting but included in simple average fallback)

## 6. Calculation Authority

### Authoritative Services
| Service | Role | I/O |
|---------|------|-----|
| `ProgressCalculationService` | PURE math engine | In: `ProgressActivityInput[]` → Out: `ProgressMetrics` |
| `ProgressAggregationService` | Prisma queries + delegation | In: `(orgId, eventId)` → Out: domain types |

### Authoritative API Endpoints
| Endpoint | Returns |
|----------|---------|
| `GET /api/events/[eventId]/progress` | `ProgressMetrics` + dimensional breakdowns |
| `GET /api/events/[eventId]/progress?summary=1` | `DashboardProgressSummary` |
| `GET /api/events/[eventId]/progress/identical` | `IdenticalActivityGroup[]` |
| `GET /api/events/[eventId]/progress/equipment` | Equipment drill-down |
| `POST /api/events/[eventId]/progress/recalculate` | Recalculates + syncs caches |

### Prohibited Patterns
1. **No dashboard may independently calculate execution progress**
2. **No frontend may calculate authoritative progress** (presentation-only labels are permitted with governance comment)
3. **No report may independently average activity progress**
4. **No API may independently calculate SPI** unless through the EVM adapter

## 7. Cached Progress — `Workpack.overall_progress`

### Definition
`overall_progress` is an **optional synchronized cache** — NOT the authoritative value.

### Write Authority
Only these may write `overall_progress`:
1. `ProgressAggregationService.recalculateEvent()` — bulk sync
2. `FieldExecutionService.syncWorkpackProgress()` — single-workpack sync (delegates to ProgressCalculationService)

### Read Usage
Frontend components may read `overall_progress` for display purposes. They should be annotated with:
```
// M8.13 GOVERNANCE: Reads cached overall_progress (synced by authoritative service)
```

### Stale Detection
A stale cache is detected when `overall_progress ≠ calculateProgressMetrics(activities).weightedProgress`.
The `recalculate` endpoint resolves stale caches.

## 8. SPI / CPI Governance

### EVM SPI/CPI (Cost-Based)
| Metric | Formula | Authority |
|--------|---------|-----------|
| SPI | `EV / PV` (or `BCWP / BCWS`) | `EvmCalculationService` (M8.10) |
| CPI | `EV / AC` (or `BCWP / ACWP`) | `EvmCalculationService` (M8.10) |

### Execution SPI (Duration-Based)
| Metric | Formula | Authority |
|--------|---------|-----------|
| Execution SPI | `actualWeightedProgress / plannedWeightedProgress` | `SpiAdapter` |

### Schedule Health SPI
| Metric | Formula | Authority |
|--------|---------|-----------|
| Health SPI | Duration-weighted actual vs planned | `ScheduleHealthService` (M8.8 — protected) |

> **RULE**: No API or dashboard may independently calculate SPI/CPI. Use the appropriate adapter.

## 9. Dimensional Progress

Progress can be broken down by any of these dimensions:
- **Discipline** — workpack.discipline.name
- **Contractor** — workpack.contractor.name
- **Unit** — workpack.unit.name or unit_name
- **Equipment Type** — asset.equipment_type or EquipmentType.name
- **Workpack** — workpack.id
- **Standard Activity Type** — activity.standard_activity_type.code

Each dimension uses the same weighted calculation formula applied to the filtered subset.

---

## 10. Identical Activity Intelligence

Identical activities are grouped by: `(Equipment Type, Standard Activity Type Code)`

For each group:
- `totalInstances` = count of included activities
- `completedInstances` = count where `progress_percent >= 100` or `status = 'completed'`
- `inProgressInstances` = count where `0 < progress_percent < 100`
- `notStartedInstances` = count where `progress_percent = 0` and `status ≠ 'completed'`
- `completionPercent` = `Math.round(completedInstances / totalInstances × 100)`
- `metrics` = standard `ProgressMetrics` for the group's activities

> **RULE**: `completionPercent` is instance-count-based. `metrics.weightedProgress` is duration-weighted. Both are valid but measure different things.

---

## 11. Classification of All Progress Calculations

Every progress calculation in the codebase MUST be classified as one of:

| Category | Description | May Write? | Example |
|----------|-------------|------------|---------|
| **AUTHORITATIVE** | Single source of truth | Yes | `ProgressCalculationService` |
| **ADAPTER** | Translates authoritative output | No | `SpiAdapter`, `EvmCalculationService` |
| **PRESENTATION-ONLY** | Frontend display label | No | `ScheduleContainer.tsx` tooltip |
| **SCENARIO-PROJECTION** | What-if analysis | No | `EvmScenarioProjection` |
| **PLANNING-READINESS** | Pre-execution readiness metric | No | `planningProgress` |

> **CRITICAL**: Planning readiness MUST NEVER be confused with execution progress.
