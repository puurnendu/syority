## Integration Gap Documented (Resource Constraints)

> [!WARNING]
> **ResourceConstraintService Interface Incompatibility**
> The existing `ResourceConstraintService.detectConstraints` reads directly from the production database via `prisma.activity.findMany({ where: { event_id } })`. 
> 
> Because it is hard-coupled to live database records, it **cannot** evaluate the in-memory array of `EffectiveActivity` objects generated by a Scenario, nor can it evaluate `CalculatedActivity` from the CPM engine output.

### How this was handled in Phase 2
To prevent the corruption of live data or producing invalid resource warnings during a Scenario Calculation, the ScenarioCalculationService currently **stubs** the Resource Analysis step. 

The snapshot output includes the following flag:
```json
"resource_analysis": {
  "status": "stubbed",
  "warning": "SKIPPED: ResourceConstraintService relies on live database queries and cannot process in-memory scenario data yet."
}
```

### Recommendation for Phase 3
To integrate Resource Leveling in a Scenario, `ResourceConstraintService.ts` (and `ResourcePlanningService.ts`) must be refactored to accept an injected array of activities via dependency injection rather than querying the database directly inside the function.
