## Architecture Under Test

```
Knowledge Bank → Equipment Type + Job Type → Template
    → Mandatory / Optional / Conditional → Planner → Workpack
```

## Validation: Are MANDATORY/OPTIONAL/CONDITIONAL Sufficient?

### Evidence From Corpus

| Conditionality | Evidence | Example |
|---|---|---|
| **MANDATORY** | Activities present in 100% of workpacks for an equipment type | Blinding, Deblinding, Final Hydrotest |
| **OPTIONAL** | Activities present in some workpacks, planner decides | Additional NDT, Eddy Current |
| **CONDITIONAL** | Activities present based on a condition evaluation | "If coating is damaged", "If retubing required" |

### Do We Need Additional Types?

| Proposed | Evidence | Verdict |
|---|---|---|
| RECOMMENDED | "Activities that AI/system recommends but planner can override" | **NOT NEEDED** — OPTIONAL covers this. AI can suggest via `ai_metadata_json`. |
| ALTERNATIVE | "Activity A or Activity B" | **NOT NEEDED** — Model as two OPTIONAL activities with note in description |
| EQUIPMENT-SPECIFIC | "Only for shell-and-tube HX, not plate HX" | **NOT NEEDED** — Use separate templates per equipment sub-type |
| QA-TRIGGERED | "Required if Hold Point fails" | **[RECOMMENDATION]** — Can be modeled as CONDITIONAL with condition_expression = "If Hold Point inspection requires repair" |
| QUANTITY-TRIGGERED | "Required if Scaffolding > 0" | **NOT NEEDED** — Can be modeled as CONDITIONAL |
| REPEATABLE | "May occur multiple times (e.g. Belzona application ×2)" | **⚠️ NEW REQUIREMENT** — Current model cannot express "this activity may appear N times" |

### Critical Gap: Repeatable Activities

**[FINDING]** Real workpacks contain activities that repeat:
- Belzona/Loctite compound application appears 2× in HX workpacks
- Hold Point inspections appear 8-12× in a single workpack
- Box up operations appear 3-4× (dome, channel, test ring, spools)
- Water draining/air drying appears 3× (shell side, tube side, final)

The current template model defines each activity once with a sequence number.
To handle repeatability, the planner must manually duplicate activities.

**[RECOMMENDATION]** Add `max_instances` (Int, default 1) to `workpack_template_activities`.
A value > 1 tells the planner "this activity may be instantiated multiple times."
This is a UX hint, not a constraint — planner can always add more activities manually.

### Hold Points as Discrete Activities vs QA Flags

**[CRITICAL FINDING]** M8.4.7 models Hold Points as a QA classification FLAG on activities.
But in P6/real schedules, Hold Points are SEPARATE ACTIVITIES with their own:
- Duration (typically 2h)
- Predecessors/successors
- Progress tracking (cleared/not cleared)

This means Hold Points must be representable as either:
1. A **flag** on an activity (current model) — "this activity requires QA clearance"
2. A **separate activity** in the template — "Hold Point - AI Inspection" as its own row

**[FACT]** Both representations are needed:
- Flag: For reporting ("how many activities have hold points?")
- Separate activity: For scheduling ("when does the inspector need to be present?")

**[RECOMMENDATION]** Keep the dual model:
- `hold_point_type` on the execution activity = reporting dimension
- Separate "Hold Point - ..." activities in the template = scheduling dimension
- Link them with a FS predecessor relationship

### Verdict: READY (with minor additions)

MANDATORY/OPTIONAL/CONDITIONAL are sufficient.
Add `max_instances` for repeatable activities (1 field).
Clarify that Hold Points should appear as both flags AND separate template activities.
