# M7.9.2 Infrastructure Diagnostic

This document outlines the current architecture of the Syority development and testing environment based on the Docker Compose, Dockerfiles, and environment configurations.

## Architecture & Configuration

### Services & Containers

1. **`db` (PostgreSQL)**
   - **Image:** `postgres:15-alpine`
   - **Internal Port:** `5432`
   - **Host Port:** `127.0.0.1:5433` (loopback only)
   - **Environment Variables:**
     - `POSTGRES_USER=user`
     - `POSTGRES_PASSWORD=pass`
     - `POSTGRES_DB=syority`
   - **Healthcheck:** `pg_isready -U user -d syority`
   - **Volumes:** `pgdata:/var/lib/postgresql/data`

2. **`redis`**
   - **Image:** `redis:7-alpine`
   - **Internal Port:** `6379`
   - **Host Port:** `127.0.0.1:6379` (loopback only)
   - **Command:** `["redis-server", "--appendonly", "yes"]`
   - **Healthcheck:** `redis-cli ping`
   - **Volumes:** `redisdata:/data`

3. **`migrator`**
   - **Build Target:** `migrator` (Node.js 20 base, light build)
   - **Command:** `./scripts/docker-migrate.sh` (defaults to `migrate` which calls `node ./scripts/docker-migrate.mjs`)
   - **Environment:**
     - `DATABASE_URL` inherited from environment/`.env`
   - **Dependencies:** `db` must be healthy.
   - **Strategy:**
     - If database is empty, runs `prisma db push --accept-data-loss` and marks all migrations as applied in `_prisma_migrations` via `prisma migrate resolve`.
     - If database contains tables/migrations, runs `prisma migrate deploy`.

4. **`app`**
   - **Build Target:** `runner` (standalone lean production-ready build)
   - **Exposed Port:** `3000:3000`
   - **Environment:**
     - `DATABASE_URL` (inherited from environment/`.env`)
     - `REDIS_URL=redis://redis:6379`
     - Auth and encryption variables
   - **Dependencies:**
     - `migrator` completed successfully
     - `db` healthy
     - `redis` healthy

### Host vs. Container Ports & URLs

- **Host Environment (`.env`):**
  - `DATABASE_URL=postgresql://postgres:postgres@localhost:5432/syority?schema=public`
  - `REDIS_URL=redis://localhost:6379`
- **Docker Compose Containers:**
  - Database URL within containers: `${DATABASE_URL}` (If `.env` is loaded, this will point to `localhost:5432` with `postgres:postgres` which will fail inside containers since `localhost` inside a container refers to the container itself, and the container name is `db` with port `5432` and credentials `user:pass`).
  - Redis URL within `app` container: `redis://redis:6379`
