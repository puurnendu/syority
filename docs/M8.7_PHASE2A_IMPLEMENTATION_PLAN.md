# M8.7 Phase 2A — Implementation Plan

## Goal
Harden the Activity Execution State, validate Activity Ownership, audit and harden the Workpack progress sync logic, and formalize the Field Execution Shift Context.

## Proposed Changes

### Database Schema
#### [MODIFY] `prisma/schema.prisma`
- Add `shift String?` to the `ProgressLog` model to explicitly link progress updates to a specific shift.

### Backend Services
#### [MODIFY] `src/core/execution/FieldExecutionService.ts`
- **`executeActivityAction()`:** 
  - Validate parent Workpack status (`issued` or `in_execution`). Reject mutation if invalid.
  - Require `execution_date` and `shift` in the action params.
  - Set `log_date` to `execution_date` and `shift` to the new field in `ProgressLog`.
- **`syncWorkpackProgress()`:**
  - Add filter to exclude `status: 'cancelled'` activities from the weighted progress calculation.

#### [MODIFY] `app/api/execution/activity-action/route.ts`
- Parse `execution_date` and `shift` from the request body and pass them to `executeActivityAction()`.

### Frontend
#### [MODIFY] `src/components/execution/ExecutionCockpit.tsx`
- Ensure `shiftType` ('day' | 'night') and an `executionDate` (today by default) are passed in the API calls (`handleStart`, `handleUpdateProgressSubmit`, `handleComplete`).

### Security Tests
#### [NEW] `scratch/m87_phase2a_security_tests.js`
- Create an automated test script covering EXE-01 through EXE-12 to guarantee execution guardrails are active and cross-tenant mutations are blocked.
