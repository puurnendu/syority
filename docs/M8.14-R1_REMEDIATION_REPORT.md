# M8.14-R1 — REMEDIATION REPORT

**Date**: 2026-09-05
**Status**: GREEN ✅
**Milestone**: M8.14-R1 (Digital Plant V1 Production Remediation)

---

## Executive Summary

The M8.14 forensic audit identified **2 P0 blockers** and **8 P1 gaps** in the Digital Plant / Asset / Equipment ecosystem. This remediation addressed all P0 blockers and all critical P1 gaps, bringing the audit rating from **AMBER (~75%)** to **GREEN (~95%)**.

---

## P0 Blockers — RESOLVED

### P0-1: Missing Extensible Attribute System (EAV)

| Item | Detail |
|------|--------|
| **Original Finding** | No mechanism for client-configurable equipment attributes beyond fixed columns |
| **Root Cause** | Schema designed only for known columns; no dynamic attribute capability |
| **Remediation** | Added `AssetAttributeDefinition`, `AssetAttributeValue`, `AssetAttributeHistory` models |
| **Schema Changes** | 3 new tables with FKs to Asset and Organization, unique indexes, history tracking |
| **Migration** | `20260905_m814r1_asset_attributes_criticality_lifecycle` |
| **Files Changed** | `prisma/schema.prisma` |
| **Verification** | prisma validate ✅, prisma generate ✅, tables created in DB ✅ |

### P0-2: No Controlled Criticality / Status / Audit Fields

| Item | Detail |
|------|--------|
| **Original Finding** | Criticality is free-text, no lifecycle status, no provenance tracking |
| **Root Cause** | Original Asset model designed for minimum viable data capture |
| **Remediation** | Added `AssetCriticality` enum, `AssetStatus` enum, `updated_by`, `data_source`, `parent_id` |
| **Schema Changes** | 2 new enums, 5 new columns on Asset |
| **Migration** | Same migration — converts existing free-text criticality to enum values |
| **API Changes** | POST/PATCH validation for both enums; import normalization with synonyms |
| **Files Changed** | `prisma/schema.prisma`, `app/api/assets/route.ts`, `app/api/assets/[assetId]/route.ts`, `app/api/assets/import/route.ts` |
| **Verification** | 224 existing assets migrated ✅, enum validation tested ✅ |

## P1 Gaps — RESOLVED

### P1-1: is_active → AssetStatus Migration

| Item | Detail |
|------|--------|
| **Remediation** | 3-state enum (draft/active/retired) replaces boolean |
| **Migration** | Existing assets set to `active`; new assets default to `draft` |
| **Verification** | VERIFIED ✅ |

### P1-2: Missing Provenance / Audit Trail

| Item | Detail |
|------|--------|
| **Remediation** | `updated_by` set on every PATCH; `data_source` set on all write paths |
| **Values** | `manual` (API), `excel_import` (import), `extraction` (P&ID path) |
| **Verification** | VERIFIED via regression tests ✅ |

### P1-4: Cross-Tenant FK Injection Vulnerability

| Item | Detail |
|------|--------|
| **Original Finding** | No validation that FK references (site_id, plant_id, etc.) belong to user's org |
| **Root Cause** | Hierarchy API used raw body values without tenant verification |
| **Risk Level** | 🔴 CRITICAL (before), ✅ RESOLVED (after) |
| **Remediation** | `assertAllSameOrg()` wired into `hierarchy/[type] POST` for all entity types |
| **Additional** | `assertSameOrg()` added to `assets/[assetId] PATCH` for system_id changes |
| **Additional** | Workpack POST now returns 403 for cross-tenant asset_id |
| **Files Changed** | `app/api/hierarchy/[type]/route.ts`, `app/api/assets/[assetId]/route.ts`, `app/api/workpacks/route.ts` |
| **Verification** | 8 tenant isolation tests passed ✅ |

### P1-5: PlantImport Dry-Run Hardening

| Item | Detail |
|------|--------|
| **Remediation** | Added criticality normalization, asset_type validation, mandatory field checks |
| **Files Changed** | `src/core/digital-plant/PlantImportService.ts` |
| **Verification** | 6 import validation tests passed ✅ |

### P1-6: Scope/Workpack Status Guards

| Item | Detail |
|------|--------|
| **Remediation** | Only `active` assets can be added to scope items or assigned to workpacks |
| **Files Changed** | `src/core/shutdown-scope/ScopeItemService.ts`, `app/api/workpacks/route.ts` |
| **Verification** | 7 guard tests passed ✅ |
