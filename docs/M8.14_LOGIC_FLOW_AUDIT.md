# M8.14 — Logic Flow Audit

> **Module**: M8.14 | **Date**: 2026-09-01 | **Type**: READ-ONLY

---

## Workflow Traces

### 1. TA (Turnaround) Creation

```
USER → /events/new (form)
  → POST /api/events
    → Validation: name, code, site_id, planned_start/end
    → Service: prisma.event.create()
    → Database: Event record
    → Side Effects: NONE
    → Missing: No audit log entry, no notification trigger
```

**Gaps**: ❌ No EventUnit/EventSystem auto-creation. ❌ No milestone auto-generation. ❌ No audit trail.

### 2. Asset/Equipment Creation

```
USER → /asset-register/new (form) OR /digital-plant AI extraction
  → POST /api/asset-register
    → Validation: tag_number unique per org
    → Service: AssetRegisterService.createAsset()
    → Database: Asset record
    → Side Effects: NONE
    → Downstream: Available for Workpack linking
```

**Gaps**: ❌ No auto-link to Unit/System hierarchy. Asset.unit_id/system_id are optional.

### 3. Workpack Creation

```
USER → /workpacks/new (form) OR WorkpackIntelligence instantiation
  → POST /api/workpacks
    → Validation: title, org_id
    → Service: prisma.workpack.create()
    → Database: Workpack record
    → Side Effects: workpack_id_counter increment
    → Downstream: Available for activity creation
```

**Gaps**: ⚠️ No mandatory equipment/asset link. Workpack can be created without an event.

### 4. Activity Creation

```
USER → Schedule View / Workpack Detail → Add Activity
  → POST /api/activities (or inline in workpack API)
    → Validation: description, workpack_id
    → Service: prisma.activity.create()
    → Database: Activity record
    → Side Effects: NONE
    → Downstream: Appears in schedule, progress calculations
```

**Gaps**: ❌ No auto-classification to StandardActivityType. ❌ No CPM recalc trigger.

### 5. Activity Execution Update

```
USER → Execution Cockpit / WhatsApp / Schedule View
  → PATCH /api/activities/[id] OR WhatsApp MessageProcessor
    → Validation: progress_percent 0-100, status enum
    → Service: FieldExecutionService.updateActivityProgress() OR direct Prisma
    → Database: Activity.progress_percent, status updated
    → Side Effects: FieldExecutionService.syncWorkpackProgress() → cache update
    → Downstream: ProgressCalculationService recalculates on next API read
```

**Gaps**: ⚠️ Direct Prisma update path (schedule view) bypasses FieldExecutionService.

### 6. Progress Update Flow

```
Activity.progress_percent changes
  → FieldExecutionService.syncWorkpackProgress()
    → ProgressCalculationService.calculateProgressMetrics()
    → Workpack.overall_progress cache updated
  
API consumers read:
  → GET /api/events/[id]/progress
    → ProgressAggregationService.getEventProgress()
      → prisma.activity.findMany(event_id, deleted_at:null, status≠cancelled)
      → ProgressCalculationService.calculateProgressMetrics(activities)
      → Returns AuthoritativeProgressDTO
```

**Status**: ✅ Authoritative (M8.13 Certified)

### 7. Schedule Update

```
USER → Schedule View → drag/resize or edit
  → PATCH /api/schedule/activities/[id]
    → Validation: dates, duration
    → Service: Direct Prisma update
    → Database: Activity dates/duration updated
    → Side Effects: NONE
    → Missing: ❌ No auto CPM recalculation
    → Missing: ❌ No ScheduleChangeRequest auto-creation
```

### 8. Baseline Creation

```
USER → Schedule → Create Baseline
  → POST /api/events/[id]/baselines
    → Service: ScheduleBaselineService
    → Database: ScheduleBaseline + BaselineActivity records
    → Side Effects: Snapshot of all activities
    → Downstream: EVM BCWS calculation
```

### 9. Scope Change

```
USER → Scope Change page → Create Request
  → POST /api/events/[id]/scope-changes
    → Service: ScopeChangeProposalService
    → Database: ScopeChangeRequest
  → APPROVE → ScopeChangeApplicationService.applyApprovedChanges()
    → Creates/modifies Activities
    → Side Effects: New activities auto-participate in progress denominator
```

**Status**: ✅ Verified (M8.13 Phase 3 — denominator tested)

### 10. EVM Update

```
Triggered by: baseline + actual progress
  → GET /api/events/[id]/evm
    → Service: EvmCalculationService.calculateEventEvm()
    → Reads: BaselineActivity (BCWS), Activity.progress_percent (BCWP), Activity.actual_cost (ACWP)
    → Returns: EvmSummary with SPI, CPI, EAC, ETC, VAC
```

### 11. Safety Reporting

```
USER → Safety page → Log entry
  → POST /api/events/[id]/safety
    → Service: SafetyService
    → Database: SafetyLog record
    → Side Effects: Cumulative manhours calculated
    → Downstream: TA Dashboard safety section
```

### 12. Material Update

```
USER → Materials page → Update supply record
  → POST/PATCH /api/events/[id]/materials/supply
    → Service: MaterialConstraintService
    → Database: MaterialSupplyRecord
    → Side Effects: Readiness recalculation
    → Downstream: Material readiness on TA Dashboard
```
