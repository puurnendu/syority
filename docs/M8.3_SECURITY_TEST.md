# M8.3 — Schedule API Security & IDOR Verification Report

This report documents the security audit and IDOR (Insecure Direct Object Reference) penetration tests performed on the **CPM Scheduling Engine API** (`POST /api/schedule/calculate`) and active shutdown context boundaries.

---

## 1. Security Test Matrix & Verification

| Test Code | Target Scenario | Attack Vector & Payload | Expected Result | Actual Result | Verdict |
|---|---|---|---|---|---|
| **SCHED-SEC-01** | **Tenant A Authorized Schedule** | Tenant A computes CPM schedule for owned Event A | HTTP 200 OK | **HTTP 200** | **PASS** |
| **SCHED-SEC-02** | **Cross-Tenant IDOR Attempt** | Tenant B attempts to calculate schedule for Tenant A's Event A | 404/403 Blocked (0 unhandled 500s) | **HTTP 404** | **PASS** |
| **SCHED-SEC-03** | **Malformed Event UUID** | Request with `event_id: "invalid-event-uuid"` | 400 Bad Request (0 unhandled 500s) | **HTTP 400** | **PASS** |
| **SCHED-SEC-04** | **Non-Existent Event UUID** | Request with unassigned random UUID | 404 Not Found (0 unhandled 500s) | **HTTP 404** | **PASS** |

---

## 2. Defensive Controls Implemented

1.  **Strict Multi-Tenant Scoping:** `POST /api/schedule/calculate` verifies that `event_id` belongs to `session.user.organization_id`.
2.  **Isolated Relationship Querying:** Only `ActivityRelationship` links whose `predecessor_id` and `successor_id` both belong to the current active shutdown are fed into the graph algorithm.
3.  **Defensive Cycle Handling:** Topological sort halts gracefully and returns structured diagnostic payload (`SCHEDULE_CYCLE_DETECTED`) rather than entering infinite recursion.
