## 1. Variance Formulas (ScheduleVarianceService)

### Start Variance
```
start_variance_days = (current_planned_start - baseline_planned_start) / 86400000
Sign: Positive = DELAYED, Negative = AHEAD
Precision: Rounded to 1 decimal
```
**Verified:** ✅ E-01 — diffDays(Sep10, Sep05) = 5.0 days
**Verified:** ✅ E-02 — Positive = delayed (correct sign convention)

### Finish Variance
```
finish_variance_days = (current_planned_end - baseline_planned_finish) / 86400000
```
Same formula as start variance. ✅

### Duration Variance
```
duration_variance_hours = current_duration_hours - baseline_duration
Sign: Positive = longer than baseline
```
**Verified:** ✅ (service L135)

### Float Erosion
```
float_erosion = baseline_total_float - current_total_float
Sign: Positive = float LOST since baseline
Null handling: null inputs → null output
```
**Verified:** ✅ E-04 — baseline=16, current=8 → erosion=8

### Criticality Direction
```
criticality_direction =
  (!was_critical && is_critical) → 'became_critical'
  (was_critical && !is_critical) → 'became_non_critical'
  otherwise → 'unchanged'
```
**Verified:** ✅ E-05

### Summary Thresholds
```
delayed: start_variance_days > 0.5
ahead: start_variance_days < -0.5
on_track: otherwise (|start_variance_days| <= 0.5)
```
**Verified:** ✅ E-07

### Null Handling
- Missing dates → null variance (not 0)
- Missing float → null erosion
- New activities (no baseline entry) → variance fields set to null

**Verified:** ✅ E-03, E-06

## 2. Forecast Formulas (ScheduleForecastService)

### Tier Precedence (highest to lowest)
```
1. ACTUAL:            completed activity → forecast = actual_end
2. REMAINING_DURATION: actual_start + remaining_duration → forecast = now + (remaining/hoursPerDay) days
3. EARNED_PROGRESS:   actual_start + progress > 0 → forecast = actual_start + (elapsed/progress × 100) days
4. PLANNED:           not started → forecast = planned_end
```
**Verified:** ✅ F-01 through F-06

### Earned Progress Formula
```
elapsed_days = (now - actual_start) / 86400000
total_est_days = (elapsed_days / progress_percent) × 100
forecast_finish = actual_start + total_est_days days
```
**Test:** 50% progress at day 10 → total 20 days → Sep 1 + 20 = Sep 21
**Verified:** ✅ F-03

### Edge Cases
```
Zero progress:  Guarded by (progress > 0), falls through to PLANNED
Division guard: Cannot divide by zero
Date direction: forecast CANNOT be before actual_start (math guarantees positive addDays)
```
**Verified:** ✅ F-05, F-07

### Project-Level Aggregation
```
project_forecast_finish = MAX(all activity forecast_finish dates)
project_planned_finish = MAX(all activity planned_end dates)
project_variance = project_forecast - project_planned (days)
```
**Verified:** ✅ (service L164-183)

## 3. Schedule Health Index (ScheduleHealthService)

### Weight Composition
```
Component           | Weight | Sum
--------------------|--------|-----
Critical Path (CP)  | 0.25   |
Float Erosion (FE)  | 0.15   |
Milestone Var (MV)  | 0.15   |
Resource Overload (RO) | 0.15 |
Progress Earned (PE)| 0.15   |
Baseline Var (BV)   | 0.15   |
                    |        | 1.00
```
**Verified:** ✅ G-01 — sum = 1.00

### Component Formulas

**CP (Critical Path):**
```
maxDelayDays = MAX over critical activities:
  if (planned_end && actual_end && status == 'completed')
    delay = (actual_end - planned_end) / 86400000
  else if (planned_end && status != 'completed' && planned_end < now)
    delay = (now - planned_end) / 86400000

score = max(0, 100 - maxDelayDays × 10)
```
**Verified:** ✅ G-03 — f(0)=100, f(5)=50, f(10)=0, f(15)=0

**FE (Float Erosion):**
```
Uses ScheduleVarianceService.calculateVariance()
avgErosion% = average(abs(erosion / baseline_float × 100)) across activities with non-null/non-zero baseline float
score = max(0, 100 - avgErosion% × 2)
No-baseline fallback: score = 100
```
**Verified:** ✅ G-04 — f(0)=100, f(25)=50, f(50)=0
**Verified:** ✅ G-10 — No baseline = 100

**MV (Milestone Variance):**
```
maxSlippageDays = MAX over milestones where actual_date > planned_date:
  slippage = (actual_date - planned_date) / 86400000

score = max(0, 100 - maxSlippageDays × 5)
No milestones: score = 100
```
**Verified:** ✅ G-05 — f(0)=100, f(10)=50, f(20)=0

**RO (Resource Overload):**
```
Calls ResourceConstraintService.detectConstraints(eventId, orgId)
Starting score = 100
For each constraint:
  CRITICAL: -15
  HIGH: -8
  WARNING: -3
  Additional: if constraint involves critical activity → -5

score = max(0, deducted_score)
Fallback (if ResourceConstraintService unavailable): score = 100
```
**Verified:** ✅ G-06 — Real call to detectConstraints confirmed (L222)
**Verified:** ✅ G-07 — 2×CRITICAL + 3×HIGH + 1×WARNING + 1×conflict = 38

**PE (Progress Earned):**
```
For each activity:
  actual_weighted_progress = progress_percent × duration_hours
  planned_weighted_progress = expected_progress × duration_hours
  
SPI = (Σ actual_weighted / Σ planned_weighted) × 100
score = max(0, min(100, SPI))
```
**Verified:** ✅ G-08

**BV (Baseline Variance):**
```
avgVarianceDays = average(abs(finish_variance_days)) from variance calculation
score = max(0, 100 - avgVarianceDays × 5)
No-baseline fallback: score = 100
```
**Verified:** ✅ G-09 — f(0)=100, f(10)=50, f(20)=0

## 5. Change Control State Machine

### Legal Transitions
```
proposed → approved (via reviewChangeRequest, action='approve')
proposed → rejected (via reviewChangeRequest, action='reject')
review → approved (via reviewChangeRequest, action='approve')
review → rejected (via reviewChangeRequest, action='reject')
approved → applied (via applyChangeRequest)
proposed → superseded (automatic on apply of another CR)
review → superseded (automatic on apply of another CR)
```

### Illegal Transitions (Enforced)
```
proposed → applied ❌ (L216: requires status=approved)
review → applied ❌ (L216: requires status=approved)
rejected → approved ❌ (L174: only proposed|review)
applied → anything ❌ (no method changes applied status)
superseded → anything ❌ (no method changes superseded status)
```

### Missing Transition
```
proposed → review ❌ NOT IMPLEMENTED (F-007, P2)
```
