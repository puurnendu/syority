# M8.6 AI Document Extraction Model

## 1. Extraction Lifecycle

The AI extraction process relies on analyzing available engineering documents (e.g., P&IDs, GA drawings, datasheets) and building a structured response.

### 1. Document Submission
- Planner attaches standard engineering drawings to the Workpack or directly to the Equipment via `AssetDocumentLink`.
- Planner triggers the "Extract Equipment Information" action.

### 2. Context Formulation
The AI prompt is provided with:
1. **Target Equipment Type:** (e.g., "Heat Exchanger").
2. **Existing Verified Knowledge:** Previous facts established in the system to act as a baseline and prevent duplicate extractions.
3. **Document Content:** Visual or text layers of the provided PDF/Image.

### 3. AI Candidate Generation
The AI responds with a structured schema detailing:
- Proposed `field_name` (e.g., "Tube OD")
- `value` and `unit`
- `confidence` (0.0 - 1.0)
- `source` metadata (page number, snippet context).

*Crucially, the AI is constrained from mutating the schema directly. It returns a JSON array of these field objects.*

### 4. Database Population
The backend processes this JSON response and creates a single `EquipmentKnowledgeVersion` with status `AI_CANDIDATE`.
It inserts multiple `EquipmentKnowledgeField` records linked to this version, all marked with `verification_status: AI_EXTRACTED`.

## 2. Planner Verification Lifecycle

The AI Candidate does **not** become trusted automatically.

1. **Planner Review UI:** The planner views a side-by-side comparison of the AI-extracted fields against the source documents. Low confidence fields (<85%) are highlighted in yellow/red.
2. **Editing & Curation:** The planner can accept the AI value, override it with a manual correction, or add missing fields the AI failed to detect.
3. **Commit / Verify:** The planner clicks `VERIFY EQUIPMENT INFORMATION`.
4. **Knowledge Promotion:** 
   - The `EquipmentKnowledgeVersion` transitions to `VERIFIED`.
   - The verified fields become the "trusted reference" for that equipment.

## 3. Tenant Isolation & Permissions
AI extraction runs under the context of the user. It will only have access to documents explicitly linked to the Workpack/Equipment, which inherently respects the tenant boundaries and RLS (Row-Level Security) defined by the `organization_id` on the `Asset` and `PlantDocument` tables.
