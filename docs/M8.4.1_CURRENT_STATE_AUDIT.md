## 1. WorkpackStatus Enum — SCHEMA

**Source**: `prisma/schema.prisma`

```
enum WorkpackStatus {
  pending_ai_review
  draft
  under_review
  approved
  issued
  closed
  cancelled
}
```

### FINDING: `in_execution` and `completed` DO NOT EXIST

The authoritative lifecycle requires:
```
DRAFT → UNDER_REVIEW → APPROVED → ISSUED → IN_EXECUTION → COMPLETED → CLOSED
```

**Classification: MISSING — Schema change required**

## 6. WorkflowService.ts — VALID_TRANSITIONS

```typescript
const VALID_TRANSITIONS: Record<WorkpackStatus, WorkpackStatus[]> = {
    pending_ai_review: ['draft', 'cancelled'],
    draft: ['under_review', 'cancelled'],
    under_review: ['approved', 'draft'],
    approved: ['issued', 'draft'],
    issued: ['closed', 'cancelled'],
    closed: ['draft'],
    cancelled: ['draft'],
};
```

### FINDINGS:
1. **No `in_execution` or `completed` transitions** — MISSING
2. **`issued → closed` is a direct jump** — no execution phase
3. **`issued → cancelled` allowed** — contradicts lifecycle spec
4. **No `cancel` method** in WorkflowService — dead route
5. **No submit preconditions** — empty workpacks can be submitted
6. **`reject` requires comment** — IMPLEMENTED correctly

## 10. Execution Condition Assessment

**Can Execution Condition be DERIVED from existing data?**

| Condition | Derivation Source | Feasible? |
|---|---|---|
| **WORKING** | Default when workpack is `in_execution` and no blocking constraints | ✅ YES |
| **QA_HOLD** | Open `ConstraintLog` with `category = 'inspection'` | ⚠️ PARTIAL — requires ConstraintLog to be used for QA delays |
| **MATERIAL_HOLD** | Open `ConstraintLog` with `category = 'material'` | ✅ YES |
| **SAFETY_HOLD** | Open `ConstraintLog` with `category = 'permit'` or SafetyIncident with status != 'Closed' | ⚠️ PARTIAL |
| **TECHNICAL_HOLD** | Open `ConstraintLog` with `category = 'equipment'` or similar | ✅ YES |
| **BLOCKED** | Multiple open constraints or severity = 'critical' | ✅ YES |

**RECOMMENDATION**: Execution Condition should be a **computed/derived value** from `ConstraintLog`, NOT a new persistent field. The `ConstraintLog` model already has `category`, `severity`, `status`, `raised_date`, `target_resolution`, `resolved_date`, and `impact_on_schedule` — which covers hold timing and aging.
