# M8.6 Activity Number Test Plan

This document defines the test cases for the newly designed Activity Number generation architecture.

## TEST 1: Basic Generation with Default Increment
- **Given:** Equipment `31-E-116` with Organization increment of `5`.
- **Action:** Create a Workpack with 4 template activities.
- **Expected:**
  - Activity 1: `31-E-116-0005`
  - Activity 2: `31-E-116-0010`
  - Activity 3: `31-E-116-0015`
  - Activity 4: `31-E-116-0020`

## TEST 2: Continuation on Second Workpack
- **Given:** Equipment `31-E-116` has existing activities (max serial `0020`).
- **Action:** Create a second Workpack for the same equipment, containing 2 activities.
- **Expected:** Numbering continues from the tenant scope.
  - Activity 1: `31-E-116-0025`
  - Activity 2: `31-E-116-0030`

## TEST 3: Different Equipment Scope
- **Given:** Equipment `31-E-117` with no prior activities. Increment `5`.
- **Action:** Create a Workpack with 2 activities.
- **Expected:**
  - Activity 1: `31-E-117-0005`
  - Activity 2: `31-E-117-0010`

## TEST 4: Configurable Increment
- **Given:** Equipment `31-E-118`. Organization increment changed to `4`.
- **Action:** Create a Workpack with 4 activities.
- **Expected:**
  - Activity 1: `31-E-118-0004`
  - Activity 2: `31-E-118-0008`
  - Activity 3: `31-E-118-0012`
  - Activity 4: `31-E-118-0016`

## TEST 5: Concurrency Safety
- **Given:** Equipment `31-E-119`.
- **Action:** Two separate requests to instantiate a Workpack for `31-E-119` are fired simultaneously.
- **Expected:**
  - The database constraint `@@unique([organization_id, activity_number])` ensures no duplicate Activity Numbers.
  - The generation logic correctly retries upon collision, ensuring one request gets `0005, 0010` and the other gets `0015, 0020` without throwing a 500 error.

## TEST 6: Multiple Activity Codes on Same Equipment
- **Given:** Two different Activity Codes (`ISO.BLINDING` and `INSP.VISUAL`).
- **Action:** Instantiate into the same Equipment `31-E-116`.
- **Expected:** Activity Codes are correctly logged on the row while Activity Numbers generate sequentially (`31-E-116-0035`, `31-E-116-0040`).

## TEST 7: Reusable Activity Code on Different Equipment
- **Given:** Activity Code `ISO.BLINDING` used on `31-E-116` and `31-E-117`.
- **Expected:** The code is perfectly reusable. Numbering is independently driven by the equipment tag.

## TEST 8: P6 Export Separation
- **Action:** Generate Primavera export.
- **Expected:** The export cleanly distinguishes between Activity Number and Activity ID, ensuring the scheduling identity remains unaffected by the execution numbering format.
