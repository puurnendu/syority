## Detailed Column Analysis

### Window

**A. Business Meaning**: Execution timing window. Tells the planner WHEN in the shutdown lifecycle this activity should be executed. A shutdown planner uses this to phase work into pre-shutdown preparation, operational isolation, main shutdown scope, inspection/repair, and post-shutdown restoration.

**B. Data Type**: Enumeration (5 values: PreSD, OP, SD, IR, PostSD)  
Examples: PreSD, OP, SD, IR, PostSD

**C. Ownership**: Activity + Planning

**D. Reusability**: Activity Code (not UDF — this is a classification dimension)

**E. P6 Representation**: P6 Activity Code

**F. SYORITY Status**: Activity.window (String) — EXISTS

**G. Gap**: Exists as free text. Should be constrained to enum. Should also be registered as an Activity Code dimension.

**Classification**: FACT (column exists in every Section E), INFERENCE (P6 Activity Code mapping)

---

### Operation Number

**A. Business Meaning**: Unique activity identifier WITHIN the workpack. Non-contiguous integers (gaps allowed). Combined with SAP WO number, forms the P6 Activity ID. A planner uses this to reference specific activities in predecessor logic.

**B. Data Type**: Integer (non-contiguous)  
Examples: 3, 4, 5, 7, 8, 9, 10, 11, 13, 15, 20, 30, 40

**C. Ownership**: Activity (identity)

**D. Reusability**: Activity instance field (auto-generated or planner-assigned)

**E. P6 Representation**: P6 Activity ID (as suffix: <WO>-<Op#>)

**F. SYORITY Status**: Activity.activity_number (String) — EXISTS

**G. Gap**: Exists. Data type is String, which is appropriate since Op Numbers are used as identifiers not for arithmetic.

**Classification**: FACT

---

### Activity Description

**A. Business Meaning**: Free-text description of the work to be performed. The planner composes this to communicate scope to the field crew. Contains equipment-specific details, quantities, dimensions.

**B. Data Type**: String (free text, typically 20-200 chars)  
Examples: "External Scaffolding", "Both sides-Channel Cover bolts opening for exchanger", "Tube H/J @ xx psi"

**C. Ownership**: Activity

**D. Reusability**: Activity Library attribute (normalized name) + Activity instance override (specific description)

**E. P6 Representation**: P6 Activity Name

**F. SYORITY Status**: Activity.description (String) — EXISTS

**G. Gap**: Exists. No normalization or library linkage currently enforced.

**Classification**: FACT

---

### Contractor

**A. Business Meaning**: The contractor organization responsible for executing this activity. In the HMEL corpus, this column is typically BLANK in the iPlan export — suggesting it may be populated at execution time or managed elsewhere.

**B. Data Type**: String (usually blank in corpus)  
Examples: (blank), "Radiant Hitech" (observed in JSA, not in Section E)

**C. Ownership**: Workpack (default) + Activity (override)

**D. Reusability**: Workpack attribute with optional activity-level override

**E. P6 Representation**: P6 Other (or Activity Code for contractor classification)

**F. SYORITY Status**: Workpack.contractor_id (FK) — EXISTS; Activity has no contractor_id

**G. Gap**: Workpack-level exists. Activity-level contractor assignment MISSING.

**Classification**: FACT (column exists), INFERENCE (typically workpack-level)

### Duration

**A. Business Meaning**: Planned elapsed duration for the activity. A planner uses this to schedule activities. CRITICAL UNKNOWN: whether the unit is hours, shifts, or days. The corpus shows values like 2.00, 14.00, 84.00, 160.00 — consistent with hours.

**B. Data Type**: Decimal (likely hours)  
Examples: 0.00, 2.00, 6.00, 12.00, 14.00, 24.00, 84.00, 160.00

**C. Ownership**: Activity

**D. Reusability**: Activity Library default + Activity instance override

**E. P6 Representation**: P6 Original Duration (unit conversion may be needed)

**F. SYORITY Status**: Activity.duration_hours (Decimal 8,2) — EXISTS

**G. Gap**: Exists. Unit assumption (hours) should be verified against iPlan configuration.

**Classification**: FACT (column exists), UNKNOWN (exact unit)

### Predecessors

**A. Business Meaning**: Activity dependencies in format <SAP_WO>-<Op#>. Defines the logical sequence of work. Assumed Finish-to-Start (FS) unless otherwise specified. The planner uses this to build the CPM network.

**B. Data Type**: Relationship reference (text: WO-Op# format)  
Examples: "9000009485-7", "9000009485-9", "9000009485-11"

**C. Ownership**: Activity (relationship)

**D. Reusability**: Template default predecessors + Activity instance relationships

**E. P6 Representation**: P6 Relationship (Predecessor)

**F. SYORITY Status**: ActivityRelationship (predecessor_id, successor_id, relationship_type, lag_days) — EXISTS

**G. Gap**: Exists and well-structured. Supports FS/FF/SS/SF types. CRITICAL: All corpus predecessors are INTRA-workpack (self-referencing). No cross-WP predecessors found.

**Classification**: FACT (format), FACT (no cross-WP refs in corpus)

**E. P6 Representation**: N/A (no direct P6 mapping)

### Manpower

**A. Business Meaning**: Structured crew specification. Format: "<Crew Type> (<Count> Manpower): <Duration>;". Multiple crews separated by semicolons. This is the RESOURCE ASSIGNMENT data. A planner uses this to specify what trade/crew and how many people for how long.

**B. Data Type**: Multi-value structured text  
Examples: "Cold Gang (8 Manpower): 3.00;", "Retubing Gang (4 Manpower): 2.00; Hydrojetting Gang (6 Manpower): 1.00;"

**C. Ownership**: Resource Assignment (Activity → Resource)

**D. Reusability**: Activity Library default resources + Activity instance override

**E. P6 Representation**: P6 Resource Assignment (Labor)

**F. SYORITY Status**: Activity.manpower_count (Int) + Activity.manpower_type (String) — PARTIAL; ActivityResource (resource_type, headcount, crew_size, planned_hours) — EXISTS

**G. Gap**: ActivityResource model is well-structured (headcount, crew_size, planned_hours). The Activity-level manpower_count/type fields are LEGACY — should use ActivityResource instead. Parsing the structured text into ActivityResource records is an IMPLEMENTATION task.

**Classification**: FACT (column structure), RECOMMENDATION (use ActivityResource not Activity fields)

### Sum of Estimated Man Hours

**A. Business Meaning**: Total planned labor effort. Mathematically = Σ(Duration × Manpower_Count) for all crews on this activity. A planner uses this for cost estimation, earned value, and manpower leveling.

**B. Data Type**: Decimal (hours)  
Examples: 2.00, 28.00, 36.00, 160.00, 168.00

**C. Ownership**: Activity (calculated)

**D. Reusability**: Calculated from Duration × Manpower — should NOT be stored independently

**E. P6 Representation**: P6 Budgeted Units (on Labor Resource) or UDF

**F. SYORITY Status**: Workpack.estimated_manhours (Int) — EXISTS at workpack level; NO activity-level equivalent

**G. Gap**: Activity-level man-hours MISSING. RECOMMENDATION: Derive from ActivityResource (planned_hours × headcount) rather than storing as independent field. If independent storage needed, use Activity UDF.

**Classification**: FACT (column exists), RECOMMENDATION (calculated field)
