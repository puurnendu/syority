## Origin of Level Code

**[FACT]** Level Code is iPlan field \`Operation_CustomDropDownList1\` (IPhtml.txt:67674).
**[FACT]** It is exported to P6 as Activity Code Type \`iPlan_Level code\` (ObjectId=5 in XML).
**[FACT]** In the XER, it appears as ACTVTYPE with name "iPlan_Level Code" containing 41 values.

## Origin of PREP.SCAFFOLDING / REPAIR.WELDING Codes

**[FACT]** These codes (PREP.SCAFFOLDING, ISO.BLINDING, REPAIR.WELDING, etc.) were PROPOSED in M8.4.3 as a SYORITY canonical taxonomy.
**[FACT]** They do NOT exist in iPlan source code, P6 XML, or P6 XER.
**[FACT]** Native iPlan Level Codes use equipment-prefixed format: Ex.RTub, PIP.Wel, AFC.BLD.

## Architecture Decision

**[RECOMMENDATION]** SYORITY should maintain TWO Level Code representations:

### 1. Native iPlan Level Code (for P6 compatibility)
- Stored as: `native_level_code` on Activity or ActivityLibrary
- Values: Ex.RTub, PIP.Wel, AFC.BLD, etc. (41 values)
- Purpose: Direct P6 export without transformation

### 2. Canonical SYORITY Level Code (for cross-equipment reporting)
- Stored as: `activity_code` (Family.Type)
- Values: REPAIR.RETUBING, REPAIR.WELDING, ISO.BLINDING, etc.
- Purpose: Equipment-independent aggregation for management reporting
