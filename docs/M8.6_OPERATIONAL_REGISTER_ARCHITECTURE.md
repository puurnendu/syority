# M8.6 Operational Register Architecture

## 1. Derived Registers Philosophy

Do **not** create statically maintained database tables for every operational register (e.g. `blind_register`, `nozzle_register`). Maintaining independent tables results in data desynchronization with the primary execution source of truth (the Workpack Activities).

Instead, SYORITY will use **Derived Operational Registers**.

A register is conceptually a SQL VIEW or application-level aggregation of:
`Equipment Knowledge (Static)` + `Activity / Execution Data (Dynamic)` + `Operational State (Status)`

## 2. Phase 3: The Blind Register

The first operational register implemented will be the **Blind Register**.

### Architecture
1. **Static Information (Equipment Knowledge):**
   The underlying reference facts (Location, Size, Rating, Blind Type) are derived from the `EquipmentKnowledgeField` records associated with the asset (e.g., fields tagged or categorized under "Blind Locations").
2. **Execution Information (Activity Level):**
   The status (Installed, Removed, Installation Date) is derived from the `Activity` records executing standard blinding work (e.g., `Activity Code = ISO.BLINDING`).
3. **Synthesis:**
   The Register UI / API queries the Equipment Knowledge to map all known blind locations on the equipment. It then LEFT JOINS the relevant `Activity` instances on the active Workpack to determine if those blinds are currently Installed or Pending.

### Resulting Data Structure
| Unit | Equipment | Location | Size | Rating | Type | Status |
|------|-----------|----------|------|--------|------|--------|
| CDU | E-116 | Channel Inlet | 6" | 150# | Blind | Installed (derived from Activity `31-E-116-0005`) |
| CDU | E-116 | Channel Outlet | 6" | 150# | Spectacle | Installed (derived from Activity `31-E-116-0010`) |

## 3. Future Registers

Once this architecture proves stable for the Blind Register, the exact same derived pattern can be applied to:
- Nozzle Registers
- Tube Plug Registers
- Manway Registers
- Inspection Registers

These require no new Prisma tables—just new standard Equipment Knowledge Field definitions and matching Activity Codes.
