# M8.9 SCOPE DECISION

**Date:** 2026-08-31
**Status:** PENDING DECISION

### Recommended M8.9 Scope
The recommended direction for M8.9 is **Scenario Planning & Schedule Optimization**. 
This is the smallest, highest-value increment that leverages the foundations built in M8.7 (Resources) and M8.8 (Schedule Control & Baselines). Planners currently see variances (M8.8) but lack a safe sandbox within Syority to test mitigations (duration overrides, logic changes) before pushing them to live execution. M8.9 provides an isolated branching mechanism that routes virtual data through the existing `scheduleEngine.ts` and `ResourceConstraintService`, scores the result using the M8.8 Health logic, and promotes the winner via M8.8 Change Control.

### Deferred Scope (M8.10 or later)
- **Probabilistic Risk Analysis (Monte Carlo):** Computationally heavy and requires advanced statistical modeling. Defer until deterministic scenario optimization is proven.
- **Earned Value / Cost Integration:** Belongs closer to execution and cost-control modules rather than planning optimization.
- **Multi-Event Portfolio Optimization:** Defer cross-event optimization until single-event scenarios are stable.

### Explicitly Forbidden Scope
- **DO NOT** write a new Critical Path calculation engine. All CPM must route through `src/lib/scheduleEngine.ts`.
- **DO NOT** write a new Resource Leveling algorithm. All resource logic must route through `src/core/resources/ResourceConstraintService.ts`.
- **DO NOT** modify live `Activity` records directly during scenario planning. Scenarios must use isolated delta tables to prevent data contamination.
- **DO NOT** bypass the M8.8 Change Control system for promoting scenarios to the live baseline.

### Open Decisions
1. **Schema Design:** Do we store full clones of activities for scenarios, or do we use a "delta" table (`ScenarioActivity`) that only stores overrides? (Delta is recommended for performance, but requires slightly more complex retrieval).
2. **UI Real Estate:** Does the Scenario comparison live *inside* the existing M8.8 Schedule Control Dashboard, or as a brand new mode in the Planner Workspace? (New mode recommended to avoid clutter).
3. **M8.8 DEF-01:** Should we apply the P2 `is_current` unique index fix as part of the M8.9 schema migrations? (Recommended: Yes).

### Final Recommendation
Approve the **Scenario Planning & Schedule Optimization** blueprint. 
It maximizes the ROI of M8.7 and M8.8 without duplicating architecture, solving a critical user need (safe what-if testing) and highly differentiating Syority from basic scheduling tools.
