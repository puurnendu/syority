### Problems Identified

1. **No executive summary** — Portfolio Dashboard has KPIs but they use different calculations
2. **No cross-functional view** — Each specialist dashboard is self-contained
3. **No single "TA Progress" view** — Progress data scattered across multiple views
4. **Execution Cockpit is separate** from planner-workspace — different navigation paradigm
5. **Report engine duplicates** data provider logic from report-builder

## Required Answer: Can the system establish a single authoritative source for TA Progress?

**Currently: NO.**

**Reasons:**
1. There is no `ProgressCalculationService` — each consumer calculates its own progress
2. `Activity.progress_percent` is authoritative at the activity level, but aggregation methods differ
3. `Workpack.overall_progress` is a cache that is inconsistently maintained
4. No service owns "TA-level progress" as a concept
5. The weighting method (duration vs simple vs cost) is not configurable or standardized

**Can it be established? YES** — by creating a centralized `ProgressCalculationService` that:
- Takes `Activity.progress_percent` as the single source of truth per activity
- Applies a configurable weighting method (duration-weighted recommended)
- Computes workpack, discipline, contractor, unit, and event-level aggregations
- Provides a single API endpoint consumed by all dashboards
- Automatically invalidates cached values when activities change
