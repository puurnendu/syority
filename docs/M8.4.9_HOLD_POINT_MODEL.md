## Architecture

A Hold Point in SYORITY has TWO simultaneous representations:

### 1. Scheduling Identity (HP.* Activity)

```
workpack_template_activities:
  sequence_number: 12
  activity_code: HP.POST_CLEAN
  description: "Hold Point — Post Cleaning Inspection by AI"
  duration_hours: 2
  hold_point_type: "HOLD"
```

This creates a real activity in the schedule with:
- Its own start/finish dates
- Predecessor relationships (comes after cleaning)
- Successor relationships (repair waits for this)
- Duration (typically 2h for inspector mobilisation)
- Progress tracking (0% → 100% when cleared)
- Float calculation and critical path participation

### 2. QA Control Identity (Attribute on Activity)

```
Activity:
  hold_point_type: "HOLD"    → Blocking gate. Cannot proceed to successor until cleared.
  hold_point_type: "WITNESS" → Non-blocking. Inspector should observe but work can continue.
  hold_point_type: null      → No QA requirement.
```

When `hold_point_type = "HOLD"`, the system requires a `qa_clearance_records` entry before
the activity's successors can start (or before the workpack can move to next phase).

### Witness Point

Same structure, but `hold_point_type = "WITNESS"`:
- Activity is scheduled with duration
- Inspector notification is triggered
- Work may proceed without waiting for clearance
- Clearance is still recorded for audit trail

### Evidence

From XER corpus:
- 878 activities have AI Hold Point classification
- 126 activities have TS Hold Point classification
- Hold Points appear as separate activities with 2h duration in all workpack traces
- Hold Points are FS predecessors to the next work step

### Template Usage

Templates include HP.* activities as real template rows with predecessor links:

```
Seq 8: CLEAN.MANUAL (12h)
         ↓ FS
Seq 9: HP.POST_CLEAN (2h) — hold_point_type = "HOLD"
         ↓ FS
Seq 10: PREP.SURFACE_PREP (8h)
```

The planner cannot mark Seq 10 as started until Seq 9 has qa_clearance_records.
