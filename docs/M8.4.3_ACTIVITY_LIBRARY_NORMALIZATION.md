## Normalization Approach

The M8.4.2 analysis produced 302 "candidate activities". Independent analysis shows this number is INFLATED due to:

1. **PDF extraction artifacts** — manpower data bleeding into activity names
2. **Quantity variations** — "Dismantling LPD Qty 4.00" vs "Dismantling LPD Qty 8.00" are the SAME activity with different quantities
3. **Equipment-specific descriptions** — "Insulation removal from exchanger" vs "Insulation removal from valve" are the SAME library activity
4. **Incomplete normalization** — many long raw descriptions were not normalized

## Recommended Library Size

> **[RECOMMENDATION]** The HMEL corpus supports approximately **40-45 unique Activity Library items** organized into 10 Activity Families.

> **[RECOMMENDATION]** The 302 candidates should be reduced to ~42 library items + equipment/template context.

## Normalization Decision Framework

For each candidate:

| Option | Meaning | When to Use |
|---|---|---|
| **A** — Single reusable activity | One library entry, equipment/template provides context | Activity description is the same across equipment types |
| **B** — Different library activities | Separate library entries | Activities are fundamentally different despite similar names |
| **C** — Base + specialized variants | One base library entry with parameterized variants | Same core activity but distinct sub-types exist |
