# M8.13 Risk Register

## Pre-Implementation Risks

| ID | Risk | Severity | Likelihood | Impact | Mitigation |
|----|------|----------|-----------|--------|-----------|
| R-01 | **Progress inconsistency persists** — new service added alongside existing calculations instead of replacing them | CRITICAL | HIGH | Users see different numbers on different dashboards | Phase 2 must redirect ALL consumers to common service. Audit check at gate. |
| R-02 | **Protected file modification** — M8.13 accidentally modifies M8.8/M8.9/M8.10 certified files | CRITICAL | LOW | Regression in certified modules | Pre-commit git diff check. Architecture lock enforcement. |
| R-03 | **Performance regression** — centralized service becomes bottleneck | HIGH | MEDIUM | Dashboard load times increase | SQL-level aggregation, no N+1 queries, in-memory cache with TTL |
| R-04 | **Schema migration failure** — new StandardActivityType model migration fails | MEDIUM | LOW | Deployment blocked | Additive-only migration. No column drops or renames. |
| R-05 | **Identical activity classification** — existing activities cannot be reliably classified | HIGH | HIGH | Identical activity analysis produces incomplete results | Phase approach: classify template-created first, manual backfill for rest |
| R-06 | **Scope change denominator** — progress denominator change confuses users | MEDIUM | MEDIUM | Management misinterprets progress drops | UX: show "original scope" vs "total scope" side-by-side |
| R-07 | **EVM SPI vs Physical Progress SPI** — users confuse the two values | HIGH | HIGH | Management compares incomparable numbers | UX: clearly label "Physical SPI" vs "Cost SPI (EVM)" |
| R-08 | **Stale Workpack.overall_progress** during transition | MEDIUM | HIGH | Reports show outdated data | Auto-sync trigger on activity progress change |
| R-09 | **Multi-event aggregation leak** — aggregating across events accidentally mixes tenants | CRITICAL | LOW | Data breach | Enforce org_id + event_id in every query. Security tests. |
| R-10 | **Template/equipment type master data quality** — free-text equipment types prevent normalization | HIGH | HIGH | Equipment type → standard activity mapping fails | Data cleanup phase before classification |

## Decision Points

| Decision | Options | Recommendation | Risk If Wrong |
|----------|---------|---------------|--------------|
| Weighting method | Duration vs Count vs Cost | Duration-weighted (Method B) | Users see different numbers (R-01) |
| Cache strategy | No cache vs In-memory vs Redis | In-memory with 60s TTL | Stale data (R-08) vs performance (R-03) |
| Classification approach | Mandatory vs Optional | Optional initially, mandatory for templates | Incomplete analysis (R-05) |
| Dashboard strategy | Replace dashboards vs Add executive layer | Add executive layer, redirect specialist consumers | UI complexity |
| SPI labeling | Single SPI vs Physical+Cost | Separate "Physical SPI" and "EVM SPI" | User confusion (R-07) |
