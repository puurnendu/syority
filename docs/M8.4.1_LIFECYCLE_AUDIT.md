# M8.4.1 — Workpack Lifecycle & State Machine Audit

This document details the audit of the Workpack Lifecycle and State Machine against the authoritative M8.4 specification.

---

## 1. Required Lifecycle vs. Implemented Lifecycle

### Required M8.4 Lifecycle:
```
DRAFT ──► READY ──► ISSUED ──► IN_EXECUTION ──► QC_INSPECTION ──► COMPLETED ──► CLOSED
```

### Implemented Workflow Lifecycle (as discovered in `WorkflowService.ts`):
```
DRAFT ──► UNDER_REVIEW ──► APPROVED ──► ISSUED ──► CLOSED
  ▲             │              │                      │
  └─────────────┴──────────────┘                      ▼
                                                  CANCELLED
```

---

## 2. Detailed Gap Analysis

| Aspect | Authoritative Requirement | Current Implementation (`WorkflowService.ts`) | Classification | Impact |
|---|---|---|---|---|
| **Pre-Execution Planning States** | `DRAFT` $\to$ `READY` | `draft` $\to$ `under_review` $\to$ `approved` | **PARTIAL** | Semantic alignment: `approved` serves as the readiness gate, locking the workpack and snapshotting version. |
| **Issuance State** | `ISSUED` | `issued` (action `issue`) | **PASS** | Workpack is officially released for site execution. |
| **Execution States** | `IN_EXECUTION` $\to$ `QC_INSPECTION` $\to$ `COMPLETED` | **MISSING** in `WorkflowService.ts` (direct jump from `issued` $\to$ `closed`) | **P1 GAP** | While activities have `in_progress` and `completed` states and overall progress is computed, the parent Workpack state machine lacked explicit transitions for `in_execution`, `qc_inspection`, and `completed`. |
| **Closure Gate** | `CLOSED` | `closed` (action `close`) with gates: Category A punch items, blind removal, and QA hold points. | **PASS** | Strong validation gates verified in runtime tests. |
| **Illegal Transitions** | Rejection of illegal skips (e.g. `draft` $\to$ `closed`, `issued` $\to$ `draft`) | Enforced by `VALID_TRANSITIONS` record and `canTransition` check. | **PASS** | HTTP 400 returned on illegal actions. |
| **Audit Logging** | State change persisted to `WorkflowTransition` and `AuditLog` | Persisted via `prisma.workflowTransition.create` + `AuditService.log` | **PASS** | Full relational audit trail recorded. |

---

## 3. Required Transition Rules to Close P1 Gap

To achieve 100% compliance with M8.4 without breaking backward compatibility for existing `approved` workflows, `WorkflowService.ts` and `app/api/workpacks/[id]/workflow/route.ts` must be extended to support the full execution progression:

```
draft ──► under_review ──► approved (ready) ──► issued ──► in_execution ──► qc_inspection ──► completed ──► closed
```

Supported actions:
- `submit` (`draft` $\to$ `under_review`)
- `approve` (`under_review` $\to$ `approved`)
- `issue` (`approved` $\to$ `issued`)
- `start_execution` (`issued` $\to$ `in_execution`)
- `request_qc` (`in_execution` $\to$ `qc_inspection`)
- `complete` (`qc_inspection` or `in_execution` $\to$ `completed`)
- `close` (`completed` or `issued` $\to$ `closed`, strictly gated)
- `reject` / `cancel` / `reopen`
