## Root Cause Analysis

The M8.7 implementation was built iteratively across 6 phases (2D through 2I) by AI agents operating in a sandboxed environment that prevented runtime execution. Each phase:

1. Wrote service code referencing field names from the schedule engine output (`total_float_days`, `early_finish`) instead of the Prisma schema field names (`total_float`, `early_finish`)
2. Referenced a non-existent `name` field on Activity (correct field: `description`)
3. Could not execute `npm run build`, `npx prisma generate`, or any test scripts
4. Declared "structural verification" as equivalent to runtime testing
5. Each subsequent phase inherited and compounded errors from previous phases

The fundamental issue is that **no code was ever executed against a real database**, so field name mismatches between the Prisma schema and the service code were never caught.
