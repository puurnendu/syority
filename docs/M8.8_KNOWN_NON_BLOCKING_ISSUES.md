# M8.8 KNOWN NON-BLOCKING ISSUES

The following issues were discovered during the M8.8 final closure audit. None are categorized as P0 or P1, and they do not block production certification. They are documented here for future maintenance or M8.9.

### DEF-01 (P2): Missing DB-Level Unique Partial Index for `is_current`
- **Location:** `prisma/schema.prisma`, `ScheduleBaseline` model
- **Description:** The schema defines `@@index([event_id, is_current])`. This is a standard B-tree index, not a unique partial index. PostgreSQL currently permits multiple `is_current=true` rows for the same event.
- **Mitigation:** The application layer (`ScheduleBaselineService.assignBaseline`) mitigates this by running an explicit Prisma transaction that toggles all baselines to `is_current = false` before setting the selected one to `true`.
- **Risk:** High concurrency race conditions bypassing the ORM transaction could violate the business rule.
- **Action Required:** Add a partial unique index in a future migration:
  ```sql
  CREATE UNIQUE INDEX "ScheduleBaseline_event_id_is_current_key" ON "ScheduleBaseline"("event_id") WHERE is_current = true;
  ```
