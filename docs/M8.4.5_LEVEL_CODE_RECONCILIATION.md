## Native iPlan Level Code Architecture

**[FACT]** Level Codes are a REAL P6 Activity Code Type ("iPlan_Level Code") with 41 defined values.
**[FACT]** In iPlan source code, Level Code = Operation_CustomDropDownList1.

### Level Code Structure

The native Level Codes use an **Equipment-Prefix.Action** pattern:

| Prefix | Equipment/Domain | Example Codes |
|---|---|---|
| **Ex.** | Exchanger (Heat Exchanger) | Ex.TBRemv, Ex.TBHJ, Ex.TBInsrt, Ex.RTub, Ex.CCA, Ex.FH, Ex.TBRepl |
| **AFC.** | Air Fin Cooler | AFC.BLD, AFC.DB, AFC.HT, AFC.OPN, AFC.N/S M |
| **V&T.** | Vessels and Tanks | V&T (parent), VEC, OPN, Box |
| **PIP.** | Piping | PIP.NDT, PIP.Wel, PIP.Ere, PIP.OLS |
| **PSV.** | Pressure Safety Valve | PSV.REMV, PSV.PSV BO |
| **C.** | Column | C.TMO, C.TMB, C.Box |
| **HT.** | Heater/Furnace | HT.Box, HT.FI, HT.II&R |
| **EE.** | Electrical | EE.BBBC, EE.TR, EE.HSB |

### CRITICAL INSIGHT: Native Level Codes Embed Equipment Type

**[FACT]** Unlike the M8.4.3 recommendation of Family.Type (e.g., REPAIR.WELDING), native iPlan Level Codes embed the EQUIPMENT TYPE in the prefix (Ex.RTub = Exchanger Retubing, PIP.Wel = Piping Welding).

This means:
- PIP.Wel ≠ generic "Welding" — it specifically means **Piping Welding**
- Ex.RTub ≠ generic "Retubing" — it specifically means **Exchanger Retubing**
- AFC.HT ≠ generic "Hydrotest" — it specifically means **Air Fin Cooler Hydrotest**

## WHERE DID THE M8.4.3 "PREP.SCAFFOLDING" CODES COME FROM?

**[FACT]** The codes PREP.SCAFFOLDING, ISO.BLINDING, REPAIR.WELDING etc. were PROPOSED SYORITY canonical codes in M8.4.3. They do NOT exist in iPlan or P6.

**[FACT]** Native iPlan Level Codes use equipment-prefixed codes (Ex.RTub, PIP.Wel, AFC.BLD).

**[RECOMMENDATION]** SYORITY should maintain BOTH:
1. **Native iPlan Level Code** (for P6 compatibility and import/export)
2. **Canonical SYORITY Level Code** (for cross-equipment reporting and template library)

The canonical SYORITY code provides the equipment-independent aggregation that native codes cannot:
- AFC.BLD + V&T equivalent → `ISO.BLINDING` (total blinding progress across ALL equipment)
- PIP.Wel + any welding → `REPAIR.WELDING` (total welding progress across ALL equipment)
