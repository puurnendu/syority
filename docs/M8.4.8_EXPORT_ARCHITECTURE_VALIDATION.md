> **M8.4.8** — Adversarial Validation — Generated: 2026-08-18T07:30:48.043Z

## Requirement

> Every useful SYORITY attribute should optionally be exportable.
> An administrator should be able to tick a checkbox and export it.

## M8.4.7 Proposed: `ActivityUdfDefinition.is_exportable` + `ExportAttributeConfig`

## Adversarial Analysis

### Is `ActivityUdfDefinition.is_exportable` Sufficient?

**[FINDING]** No, because:
1. It only covers UDF-based attributes
2. Non-UDF attributes (Discipline, Phase, Equipment Tag) are native model fields, not UDFs
3. The export target (P6 Activity Code vs UDF vs Native) must be configurable

### Is `ExportAttributeConfig` Required?

**[FINDING]** Yes, but it can be DEFERRED to P1.

**Reasoning**:
- For M8.5, the export paths are KNOWN and FIXED (we know exactly what goes where)
- The admin UI to toggle export is a nice-to-have, not a blocker
- The initial implementation can hardcode the known export mappings
- ExportAttributeConfig becomes valuable when SYORITY supports multiple customers with different P6 configurations

### Revised Recommendation

**For M8.5 (P0)**:
- `ActivityUdfDefinition.is_exportable` — KEEP (simple flag for UDF-based exports)
- `ExportAttributeConfig` — DEFER to M9

**For M9 (P1)**:
- `ExportAttributeConfig` table with full admin UI

### Verdict: READY (with P0/P1 split)
