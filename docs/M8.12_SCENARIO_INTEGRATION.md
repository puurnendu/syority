# M8.12 — Scenario Integration

**Status**: LOCKED  
**Date**: 2026-09-01

---

## Principle

Scenario calculations MUST NOT mutate:
- Material records
- Supply records
- Activity records
- Workpack records
- PO data
- Live schedule

---

## Scenario Material Constraint Projection

When `ScenarioCalculationService.calculate()` runs:

1. Resolve effective activities (existing step)
2. **NEW**: Load material constraints for those activities (read-only)
3. **NEW**: For scenario overrides that change activity planned_start:
   - Recalculate whether the material constraint is still binding
4. Inject material constraint dates into activity planned_start (pre-CPM)
5. Run CPM engine (existing step)
6. Run resource analysis (existing step)
7. Compute health metrics (existing step)

### What-If Material ETA Changes

Scenarios should support:
```
"What if Material X arrives 2 weeks late?"
"What if we substitute Material Y?"
"What if we split the activity to start partial work?"
```

This requires a `ScenarioMaterialOverride` concept:

```prisma
model ScenarioMaterialOverride {
  id                String    @id @default(uuid()) @db.Uuid
  scenario_id       String    @db.Uuid
  material_line_id  String    @db.Uuid
  override_eta      DateTime? @db.Date
  override_quantity Float?
  override_status   String?   // e.g., "available", "delayed"
  notes             String?
  created_at        DateTime  @default(now())

  scenario          ScheduleScenario @relation(fields: [scenario_id], references: [id])
  @@map("scenario_material_overrides")
}
```

**Status**: RECOMMENDED — not required for M8.12 MVP. Can defer to M8.13.

## Non-Mutation Guarantee

| Data | Scenario Behavior |
|------|-------------------|
| `workpack_material_lines` | READ ONLY |
| `MaterialSupplyRecord` | READ ONLY |
| `MaterialConstraint` | READ (live values) or OVERRIDE (scenario) |
| `Activity` | READ ONLY (scenario uses overrides table) |
| `ScheduleBaseline` | READ ONLY |
| M8.10 EVM snapshots | READ ONLY |

---

## Integration with Existing Scenario Architecture

M8.9 scenarios use `ScenarioActivityOverride` to override activity fields without mutating the live schedule. Material constraints follow the same pattern:

- **Live calculation**: Uses actual material data
- **Scenario calculation**: Uses actual material data + scenario material overrides
- **No mutation**: Both paths produce projection results only

---

## Recommended M8.12 Scope

For M8.12 MVP, scenario integration should:
1. READ live material constraints during scenario calculation
2. Include material constraint impact in scenario health metrics
3. Defer `ScenarioMaterialOverride` to M8.13

This keeps M8.12 focused on the core material-to-CPM integration while preserving the scenario architecture for future what-if analysis.
